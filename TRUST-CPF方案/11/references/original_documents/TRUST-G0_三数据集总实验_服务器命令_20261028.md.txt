新项目：`/var/tmp/xhw/trustg0_three_v1_10ep`。账号：`xhw@211.87.232.122`。**只使用 GPU 0、1、2**。所有新增缓存、日志与权重写在 `/var/tmp/xhw`；原 `/data` 数据集和 CLIP 权重只读取。

## 1. 停止当前 CPF 复现任务

在本机 Windows PowerShell 执行：

```powershell
scp -o ServerAliveInterval=30 -o ServerAliveCountMax=6 "C:\Users\llenovo\Documents\ChatGPT\USG\output\stop_CPF_repair_20261028.py" "xhw@211.87.232.122:/var/tmp/stop_CPF_repair_20261028.py"
```

在服务器终端执行：

```bash
conda activate vgcpod_v1
python /var/tmp/stop_CPF_repair_20261028.py --project /var/tmp/xhw/cpf_repair_v1_10ep --apply
```

看到 `CPF_PROJECT_STOPPED` 或 `ALREADY_STOPPED` 即可。脚本按项目绝对路径和当前用户匹配队列、训练进程及子进程；已有实验文件保留。不要使用 `pkill python`。

## 2. 上传新包

回到本机 Windows PowerShell 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\llenovo\Documents\ChatGPT\USG\trustg0_three_v1_10ep\scripts\upload.ps1"
```

脚本上传本地 `trustg0_three_v1_10ep.zip` 及其 `.sha256`，服务器目标为 `/var/tmp/xhw/`。每段命令自己定义路径，不依赖前一个 PowerShell 会话的变量。

## 3. 服务器解压与准备

在服务器执行整段：

```bash
conda activate vgcpod_v1
cd /var/tmp/xhw
sha256sum -c trustg0_three_v1_10ep.zip.sha256
python -m zipfile -e trustg0_three_v1_10ep.zip /var/tmp/xhw
cd /var/tmp/xhw/trustg0_three_v1_10ep
bash scripts/prepare.sh
```

成功标志为 `TRUST_G0_READY_GPUS_0_1_2`。prepare 会安装缺少的依赖、执行数值测试、读取之前 Pure 项目的数据路径和 CLIP 权重路径、扫描三数据集、核对自然划分、生成三 seed 五折索引。它使用的来源为：

```text
/data/xhw/experiments/trustcpf_pure_v1_10ep/work/identity.json
```

沿用此文件中已经核对的 UT、MIT、C-GQA 位置，避免重新手填路径。只读取其数据索引，不复用当前 CPF 复现权重。CLIP 图像与文本缓存由后续队列自动生成。

## 4. 启动完整三卡队列

服务器执行：

```bash
cd /var/tmp/xhw/trustg0_three_v1_10ep
mkdir -p logs
nohup bash scripts/run_all.sh 0 1 2 > logs/queue.log 2>&1 &
echo $! > logs/queue.pid
tail -f logs/queue.log
```

在 `tail -f` 中按 Ctrl+C 只退出查看。三张卡动态接任务，每卡一个进程；队列不使用 3 号卡。阶段依赖与已完成标记自动处理，无需手动启动第二批。

## 5. 查看具体进度

服务器任意新终端执行：

```bash
conda activate vgcpod_v1
cd /var/tmp/xhw/trustg0_three_v1_10ep
python scripts/status.py
```

持续刷新：

```bash
watch -n 30 python scripts/status.py
```

查看总队列：

```bash
tail -n 40 logs/queue.log
nvidia-smi
```

查看单个任务（示例）：

```bash
tail -f logs/base_ut-zap50k_5351.log
```

教师任务日志示例为 `logs/teacher_ut-zap50k_5351_t1_q1.log`；正式评估为 `logs/finish_ut-zap50k_5351.log`。`status.py` 会显示正在运行的具体日志路径、epoch/batch、干预测量进度以及每套流水线完成的教师和读出数量。

完成标准：队列输出 `ALL_G0_TRUST_EXPERIMENTS_COMPLETE`；状态为 9 套流水线完成，每套 15 个教师、45 份读出、3 份 Q5 教师决策审计，正式指标合计 1620 行。

任务报错时，先查看 `queue.log` 指出的单任务日志。解决后再次执行第 4 步即可恢复；成功完成的任务自动跳过。日志覆盖只影响总队列查看文件，单任务日志以追加方式保存。

脚本自动下载、验证 SHA256、解压并核对 9 套流水线和 1620 行指标。成功输出 `DOWNLOAD_SHA256_EXTRACTION_COMPLETE` 和具体保存路径：
