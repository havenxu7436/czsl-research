TRUST-CPF / CLIP 服务器实践命令

1. 从第四条路线恢复执行包

在服务器已克隆的czsl-research仓库根目录执行：

git lfs pull
python tools/register_trustcpf_v1.py --check
export REPLAY="$HOME/experiments/trustcpf-replay-v1"
python tools/reproduce.py materialize --line TRUST-CPF方案 --stage v1 --dest "$REPLAY"
export TRUST_PKG="$REPLAY/trustcpf_clip_v1"
cd "$TRUST_PKG"
export CPF_PY="$(command -v python)"
export DATA_ROOT=/srv/czsl-project/data/ut-zap50k
export CLIP_CKPT="$HOME/.cache/clip/ViT-L-14.pt"
export CACHE="$HOME/experiments/trustcpf_clip_v1/cache/ut-zap50k"
export WORK_ROOT="$HOME/experiments/trustcpf_clip_v1/work"
source scripts/env.sh
"$CPF_PY" -c 'import torch; print(torch.__version__,torch.cuda.get_device_name(0))'
"$CPF_PY" -m pip install -r requirements.txt
"$CPF_PY" -m unittest discover -s tests -v

REPLAY为新的绝对目录。CPF_PY取当前已激活CZSL环境解释器，也可指定/srv/czsl-env/bin/python。DATA_ROOT、CLIP_CKPT改为服务器已有数据与权重位置。沿用Python3.8/torch1.13环境时依赖下限可满足；当前源码通过Python3.8语法检查。

数据与权重的文件身份见external_inputs.json。使用离线部署ZIP时，将ZIP解压到新的执行目录即可，包内布局与materialize结果一致。

2. 一次性准备

CUDA_VISIBLE_DEVICES=0 bash scripts/prepare.sh

已有VG-CPOD g/fa/fo缓存时直接指定其目录：

export CACHE=/srv/czsl-runs/vgcpod/cache/ut-zap50k
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py graph --cache "$CACHE" --checkpoint "$CLIP_CKPT"

图准备新建graph.pt和knowledge_manifest.json，原图像/文本缓存继续复用。特征维度分别为768/16×768/12×768。graph.pt包含96条边、28个原语锚点和全部源知识向量。

3. 第一轮正式实验

mkdir -p "$WORK_ROOT" logs
CUDA_VISIBLE_DEVICES=0 nohup bash scripts/train_seed.sh 3351 > logs/seed3351.log 2>&1 &
tail -f logs/seed3351.log

完整队列不按准确率设置停跑阈值。教师各10epoch、测量拟合折各512任务、开发/审计各128任务、效用三模型最多50epoch、参考教师10epoch、每对照适配3epoch；由VAL CW AUC选择同一权重评价CW/OW。

4. 三seed并行

图像缓存共享，work分别存放：

CUDA_VISIBLE_DEVICES=0 nohup bash scripts/train_seed.sh 3351 > logs/seed3351.log 2>&1 &
CUDA_VISIBLE_DEVICES=1 nohup bash scripts/train_seed.sh 3352 > logs/seed3352.log 2>&1 &
CUDA_VISIBLE_DEVICES=2 nohup bash scripts/train_seed.sh 3353 > logs/seed3353.log 2>&1 &

只有一张GPU时依次执行三条前台bash scripts/train_seed.sh SEED。多GPU是三条独立单卡进程，每进程的cuda对应CUDA_VISIBLE_DEVICES选出的物理卡。

5. 逐阶段命令与恢复

export WORK="$WORK_ROOT/seed3351"
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py teachers --cache "$CACHE" --work "$WORK" --seed 3351 --fold all
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py measure --cache "$CACHE" --work "$WORK" --seed 3351 --fold all
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py fit --cache "$CACHE" --work "$WORK" --seed 3351
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py audit --cache "$CACHE" --work "$WORK" --seed 3351
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py tune --cache "$CACHE" --work "$WORK" --seed 3351
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py fit --cache "$CACHE" --work "$WORK" --seed 3351 --fit-all
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py reference --cache "$CACHE" --work "$WORK" --seed 3351
CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py structure --cache "$CACHE" --work "$WORK" --seed 3351
for VARIANT in r0 capacity dense drop free mean robust; do
  CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py adapt --cache "$CACHE" --work "$WORK" --seed 3351 --variant "$VARIANT"
done
"$CPF_PY" run.py report --cache "$CACHE" --work "$WORK"

恢复时重跑对应阶段的原命令。teachers --fold 3仅处理第3折；已完成fold测量文件直接读取。变更方法参数时使用新的work目录，以区分实验身份。

6. 知识内容和噪声实验

CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py pipeline --cache "$CACHE" --work "$WORK_ROOT/shuffled3351" --seed 3351 --variant shuffled
CUDA_VISIBLE_DEVICES=0 bash scripts/noise.sh 3351

完整噪声队列为4组×5扰动seed×3关系类型×5强度×2扰动方式。快速检查一条噪声曲线：

CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py noise --cache "$CACHE" --work "$WORK_ROOT/seed3351" --seed 3351 --variant robust --noise-seeds 7101 --rates 0 0.1 0.3 0.5

噪声实验固定干净VAL bias和温度，不用噪声TEST选参。效用组从已有TRAIN摘要预测变化知识的结构，无需新增效用标签。

机制拆解另外提供纯语义、20%未测边配置。两者可复用已有五折教师和配对测量，只重拟合效用并审计：

for ABLATION in semantic unmeasured; do
  export ABLATION_WORK="$WORK_ROOT/${ABLATION}3351"
  mkdir -p "$ABLATION_WORK"
  ln -s "$WORK_ROOT/seed3351/measurements" "$ABLATION_WORK/measurements"
  CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py fit --cache "$CACHE" --work "$ABLATION_WORK" --seed 3351 --config "configs/$ABLATION.json"
  CUDA_VISIBLE_DEVICES=0 "$CPF_PY" run.py audit --cache "$CACHE" --work "$ABLATION_WORK" --seed 3351 --config "configs/$ABLATION.json"
done

类型常数和边查表对照由每次audit自动写入。unmeasured按关系类型固定留出20%边，不参与效用拟合和开发NLL选模，并单列其Q5结果。
