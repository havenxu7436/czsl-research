## 3. 增加 Epoch 后，什么判断发生了变化

![十轮训练曲线](C:/Users/llenovo/Desktop/UT_description_review/EKR_v2十轮训练曲线_20261008.png)

蓝线是名称组，红线是正确描述加对齐，紫线是错配描述，绿线是正确描述但固定 value。阴影区为从旧实验保留的 1–3 轮，右侧为新训练的 4–10 轮。虚线是冻结 B_name 锚点。

### 3.1 名称组：三轮确实可能漏掉收益

旧三轮选择 epoch 0；扩到十轮后选择 epoch 6。相对锚点，CW AUC +0.353 pp、CW HM +1.864 pp、OW AUC +0.743 pp、OW HM +1.745 pp。

这直接说明之前“三轮没收益就认为这个分支没用”的结论太强。名称组值得保留为候选。但十轮中只有第 6、7 轮 CW AUC 高于锚点，最后一轮反而低 0.451 pp；单 seed 上选择到一个最佳轮并不证明稳定收益。若确认这项工程改进，应在固定协议下补其他训练 seed，不能将 epoch 6 固定为所有新 seed 的最佳轮。

### 3.2 正确描述加对齐：十轮仍没有延迟收益

十个训练轮次都低于锚点。最好的训练轮为第 1 轮，CW AUC 42.963%，仍低 0.160 pp；第 10 轮为 42.226%，低 0.897 pp。第 8–10 轮平均为 42.233%，低于第 1–3 轮平均的 42.792%。

训练 loss 的早期三轮平均约 1.312，后期三轮约 1.245；梯度和残差均非零。模型确实在更新，但训练目标改善没有转化为 CW AUC 改善。这更符合“当前目标或表示在验证集上没有形成所需增量”，而不是“训练没有启动”。损失与 AUC 不同向不单独证明过拟合，也不证明永远不会出现更晚收益。

### 3.3 固定 value：收益很小，且不是后期才出现

最佳轮仍为 epoch 2，CW AUC +0.084 pp、OW AUC +0.244 pp；增加七轮没有刷新最佳值。可学习对齐没有胜过这个消融。固定 value 组可训练参数为 28,834，另外三组为 48,034；因此它是机制消融，不能当作严格等容量的主对照。

## 4. Gate 为什么仍为 false，能不能忽略

主组是 `V_clean_align`，不能因为名称组获得收益，就把名称组的成绩代入原描述贡献 gate。

| 正确描述加对齐相对对照 | 实际差值 | 原要求 | 结果 |
| --- | ---: | ---: | --- |
| B_name：CW AUC | 0.000 pp | ≥ +0.2 pp | 未通过 |
| 名称加对齐：CW AUC | -0.353 pp | ≥ +0.2 pp | 未通过 |
| 错配描述加对齐：CW AUC | 0.000 pp | ≥ +0.2 pp | 未通过 |
| 名称加对齐：CW HM | -1.864 pp | ≥ -0.5 pp | 未通过 |
| 名称加对齐：OW AUC | -0.743 pp | ≥ -0.5 pp | 未通过 |

另外四个 guard 通过；正确描述加对齐相对固定 value 的 CW AUC 为 -0.084 pp，也不支持对齐消融要求的 +0.1 pp。

**这次不属于“正收益只是差一点达到阈值”。** 即使把 +0.2 pp 降低，正确描述仍低于名称对照，并触发两项退化 guard。忽略 gate 不会增加正确描述有效的证据。保留旧 gate 的 false；可以另立新的探索协议，不能把新的研究问题写成旧 gate 已通过。

不执行旧 `run_confirm.sh` 或旧阶段 C。需要保留所有正、负结果和服务器权重，包括选中第 0 轮的组。

## 5. 对象条件机制的额外诊断

我从完整分数中计算每张图像的新增残差，并在同一属性下减去不同候选对象的残差均值。这只检查新增分支，冻结 CPF/名称锚点仍可能依赖对象。

| 新增分支及检查点 | 残差平均绝对值 | 同属性内随对象变化的平均绝对值 | 变化/总残差 |
| --- | ---: | ---: | ---: |
| 名称对齐，选中 epoch 6，CW | 0.023672 | 0.00000000951 | 0.0000402% |
| 名称对齐，选中 epoch 6，OW | 0.024614 | 0.00000001023 | 0.0000416% |
| 正确描述对齐，训练 epoch 10，CW | 0.031329 | 0.000686 | 2.191% |
| 错配描述对齐，训练 epoch 10，CW | 0.032007 | 0.001160 | 3.624% |

名称组四个槽都是同一个属性名称，经过共享 value 对齐后仍相同；不同对象只能通过 null 权重影响新增输出。选中 checkpoint 的平均 null 权重约 0.0000173，几乎关闭 null。源码结构与上述分数结果共同表明：**这次名称组收益主要表现为近似不依赖候选对象的属性名称对齐。** 它可以是有用的属性分数修正，但不能作为“对象条件多描述检索成功”的证据。

正确描述组的 value 漂移从第 1 轮约 0.608 增至第 10 轮约 0.675，eta 接近允许区间下界（约 -0.094，界限为 -0.1）。这些是表示明显被改写、残差增大的迹象；负 eta 在当前设计中合法，不是单独的 bug。漂移也不单独证明语义被破坏或解释失败的因果原因。与错配对照一起看，本轮尚未证明学到了有收益的正确描述对应关系。

## 6. 下一步建议与执行顺序

### 推荐主线：保留 C_text，改为原路径 3 的条件属性概率验证

原静态 v2 的 C_text 有三个 seed、每项十轮支持：相对 A_unit 平均 CW AUC +3.067 pp、OW AUC +4.131 pp。正确描述相对错配的 CW 筛选仍未通过，不能把全部增益当成知识归属收益；但它是已有证据较强的工程基线。

我建议下一轮主线沿用已拟定的 [知识条件概率实践方案](C:/Users/llenovo/Desktop/UT_description_review/知识条件概率建模_下一步稳妥实践方案_20261008.md)：在共同冻结的 C_text 上，用候选对象、图像和经审阅的 OE/AE 生成低秩属性证据，直接训练条件属性似然，首轮关闭额外逻辑损失和 backbone 微调。

具体顺序：

1. 固定新探索协议，保留所有旧失败记录。保持字典 v2、GloVe、split、原 evaluator、VAL 主指标和十轮预算；不再改句子、边跑边改 gate。
2. 先实现并核验零增量时完整回放 C_text，以及候选对象实际影响新增属性条件概率；不以非零注意力或残差本身作为有效性证明。
3. 进行名称、正确 OE/AE、错配 OE/AE 的等容量配对十轮 pilot，并保留每轮分数。只有正确知识相对两个主对照有增量且 guard 合格，才另立多 seed 确认协议。
4. 确认阶段保持每个 seed 内共同锚点、相同初值与数据顺序；按同一选择规则独立选轮。确认结束再锁定模型和测试协议，不使用 TEST 来选改动。

这改变的是知识进入模型的位置和训练目标，保持原路径 3 的核心问题 `P(a | o,x,K)`。它是新的实现假设，尚未实现或训练；无法依据目前的四组结果给出可靠的成功百分比。

### 可选的小预算工程支线：确认名称对齐

如果优先目标是确认一个已有正向信号，可补 seed 3351、2026：每个 seed 用各自 A_unit 和名称锚点建立共同 B_name，再训练 `V_name_align` 到十轮，在该 seed 内与 B_name 配对；同时登记两层名称分支的训练预算。它验证“名称对齐的工程增益”，不能代替描述知识贡献实验。

不建议为获得正数而同时扩多 seed、加轮次、换基线、换字典、换损失。也不建议先把旧 N_name 锚点再训十轮后重跑本次四组：当前共同锚点虽来自三轮 N_name，但在四组间固定，已足以回答本轮十轮残差比较。若下一步重新训练锚点，应归入新协议并对主对照共享。

此次没有继续训练 SG-EKR 三组，因此不能将本轮十轮结果写成 SG-EKR 的十轮确认失败。

## 7. 已完成实验的价值

已有工作有三项可复用产出：通过校验的知识字典和配对数据流程；静态 C_text 的三 seed 强工程起点；本次预算复核揭示的“名称对齐有延迟信号，正确描述对齐没有形成验证收益，对象条件作用较弱”。它们有助于减少后续无效搜索，也形成了机制消融证据。
