# Epoch 回溯审查与 v2 十轮续训方案

日期：2026-10-08。回溯资料包括原阶段 8 项 MVP 记录、UT 静态 v2 审阅、名称锚点三轮 pilot、共享值对齐 v2 三轮 pilot、TRAIN 支持探针和 SG-EKR 三轮 pilot。原结果均保留。

**决定回到 EKR v2 的“共同名称底座＋原始语义槽＋共享值对齐”四项实验，从完整第 3 轮断点续到总计第 10 轮。此次只改训练轮数。**

这一步位于 TRAIN 支持筛选和 SG-EKR 之前。它拥有完整描述输入、同结构同容量的三个主对照及固定 value 消融，可以同时检查“是否只是短训误筛”和“value 对齐是否有增量”。不重新训练静态 CPF，不重做描述审核，不同时改 anchor、LR、rank、温度、mask 或 loss。

## 2. 为什么只回到这个起点

v1 的正确描述使用中心化值，名称对照使用名称/2，两者的 value 几何不同。v2 已修复这一问题：保留自身名称，使用原始单位语义槽，三个主组拥有相同的 48,034 个可训练参数与相同初始参数。固定值消融有 28,834 个可训练参数，单独标记为消融，不能冒充等容量主对照。

v2 的本地审计已独立重算 22 次原生 VAL 评估、132 个指标，最大差异 0.0 pp，图像、候选和标签配对通过；epoch 选择和旧 gate 也独立核对。这些是记录与分数的证据，不等于本地独立 GPU 推理。

SG-EKR 加入了从 TRAIN 证据筛选槽的额外假设。先回到完整原始槽的 v2，能更直接检查之前放弃共享对齐是否受三轮预算影响。此次无需回到更早的 CPF/字典阶段。

共同底座仍固定为旧 A_unit 与旧 N_name 的第 3 轮选中权重。A_unit 来自已完成的十轮实验；N_name 是三轮训练后被冻结的已有模型。后者仍是研究范围限制：本次只能判断这个固定底座上的额外分支，不能证明名称底座已充分训练。所有四组共享它，因此预算比较仍成立。同步延长名称底座会改变基础分数，需要新的独立配对设计；此次不同时改变这个因素。

## 4. 固定的续训范围

- seed 0；四组各从 epoch 3 续至 epoch 10，共新增 28 个 epoch。
- 保持原 optimizer、LR=0.001、weight decay=0.0001、batch size=64、温度、rank、loss、bank、固定 shuffle 与数据划分。
- 从 last_epoch.pth 恢复模型、optimizer 和 Python/NumPy/torch/CUDA/DataLoader RNG，不能从 best checkpoint 伪装恢复 epoch 3。
- 保存并保留 epoch 1–3 的旧评估证据，新增每轮 CW 全量分数。所有组在 epoch 0–10 中选第一个严格 CW AUC 最大值，然后执行最终 CW/OW。
- 维持原 +0.2 pp 主收益要求和保护条件；共享对齐相对 fixed 的 +0.1 pp 单独记录。旧所有 gate 仍为 false。
- 不读 TEST、不追加到过线为止、不删除不利组。10 epoch 是固定预算上限，不是收敛保证。

如果主候选出现相对两个主要对照的优势，下一步冻结该实现，再安排固定的 seed 3351/2026 配对确认。若只有 fixed 有信号，对齐并未获得支持；需要在另立协议下补等结构的固定值名称/错配对照，才能检查 fixed 的描述归因。如果各组仍无优势，降低当前实现优先级，保留视觉原型方案作为候选；单 seed、十轮仍不能否定全部 EKR 实现。

```bash

```

这条恢复命令会验证已完成组并跳过，从最后提交的 epoch 继续未完成组。首次导入应看到 `BUDGET IMPORT PASSED`，接着出现 `RESUME AFTER COMMITTED EPOCH 3` 和 `epoch=4`。完整汇总的标志是 `BUDGET10 DECISION` 与 `DOWNLOAD V2 REVIEW ZIP`。

如果旧断点缺失、hash 不符或回放失败，脚本会停止并保留日志。不要拿 best checkpoint 替代 last_epoch，不要编辑 gate 来绕过检查。
