## 2. OI、OE、AE 的实际 schema

### 2.1 OI：对象的父概念归属

数据类型为 `dict[str, list[str]]`，键为父概念，值为数据集中的对象标签列表。UT 文件中的真实片段：

```json
{
  "boot": ["Boots.Ankle", "Boots.Knee.High", "Boots.Mid-Calf"]
}
```

文件存储方向是“父概念→对象”，语义可解释为“对象属于父概念”。每个对象在所有成员列表中恰好出现一次；父概念不是额外的组合类别。当前 C 的 forward 没有使用 OI 进行图传播或父类逻辑约束，OI 目前用于资产覆盖与来源记录。

### 2.2 OE：对象的文本描述

数据类型为 `dict[str, list[str]]`，键是对象原始标签，每个值有三条描述。真实片段：

```json
{
  "Boots.Ankle": [
    "shaft ending at the ankle",
    "closed toe boot silhouette",
    "low boot collar"
  ]
}
```

所有键及其顺序必须与 `objects.txt`、cache manifest 中 `objs`、实际 dataset 对象列表一致。这些描述属于对象原语，未按 train/val/test 组合分别生成。

### 2.3 AE：属性的文本描述

同样为 `dict[str, list[str]]`，键是属性原始标签，每个值有三条描述。真实片段：

```json
{
  "Canvas": [
    "woven canvas fabric",
    "coarse textile surface",
    "matte cloth finish"
  ]
}
```

所有键及顺序必须与 `attributes.txt`、cache manifest 中 `attrs`、dataset 属性列表一致。当前实现先将描述聚合为一个原语向量，没有逐描述注意力、随机图采样或完整逻辑损失。

### 2.4 数量与覆盖

| 数据集 | 属性 M | 对象 N | OI 父概念 | OI 成员数 | OE 描述数 | AE 描述数 | 来源/审核行数 N+M | K 的形状 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| UT-Zappos50K | 16 | 12 | 4 | 12 | 36 | 48 | 28 | [12,16] |
| MIT-States | 115 | 245 | 19 | 245 | 735 | 345 | 360 | [245,115] |
| C-GQA | 413 | 674 | 23 | 674 | 2022 | 1239 | 1087 | [674,413] |

这些数量已在本机 draft 核验。服务器汇总时重新计数并核对冻结来源。OE/AE 的数量表示“存储的描述文本条目”，不等于独立图节点或独立观测样本数；文本可能存在重复或近义模板。

## 3. 来源与审核文件

UT 是手工重构知识；MIT/C-GQA 的本机源 manifest 标明 `Princeton WordNet 3.0 first-sense lexical draft`。它们并非 LOGICZSL 官方知识，也不能写成已经得到 GPT-4 生成与人工核验的官方资产。

`entry_provenance.csv` 每个对象/属性一行：

| 字段 | 含义/记录方法 |
|---|---|
| `kind` | `object` 或 `attribute` |
| `label` | 数据集原语标签，与 JSON 键对齐 |
| `query` | WordNet 查询用词；手工 UT 可以为空 |
| `synset` | 采用的词义 ID，例如 `aluminum.n.01` |
| `sense_count` | 检索出的候选词义数，多义词需重点检查 |
| `used_head_fallback` | 是否使用词头回退；保留原值，不当作已审核正确 |
| `parent` | 所分配父概念；用于解释 OI 来源 |
| `quality` | 来源质量标签，如 `wordnet_auto_unreviewed` |
| `review_reason` | 待审原因，例如多义词首义选择 |

`review_status.csv` 字段为：

```text
kind,label,status,reviewer,date,note
```

每个原语一行，当前 builder 接受的状态是 `approved`。**脚本批量设置 approved 是信任操作，不证明人工逐条复核**。报告同时记录 cache `knowledge_status`、source manifest 的 `status`、review 的 approved/pending 数量及说明。当前截图中的训练缓存为 `bulk_trusted_unverified`。

本机保存的原始 draft 当前是 UT 28、MIT 360、C-GQA 1087 行 `pending`；这是本机归档状态，不能推断服务器 bulk-trusted 副本还是 pending。反过来，服务器通过 `--require-reviewed` 也不能将本机 draft 写成已完成人工审核。

原始来源 CSV 若不在 builder `input_sha256` 中，新工具将标为 `current_supplement_not_frozen_input`：它是补充证据，不能宣称其字节在训练前已经冻结。

## 4. 模型缓存的目录与矩阵轴

```text
/data/xhw/czsl_repro/knowledge/kcc0601_v1/cache_trusted_v1/
├── ut-zap50k/
├── mit-states/
└── cgqa/
    ├── labels.json                 # {"attrs": [...], "objs": [...]}
    ├── W_o_name_raw.pt             # [N,300] 原 baseline 对象名称向量
    ├── W_a_name_raw.pt             # [M,300] 原 baseline 属性名称向量
    ├── W_o_name_unit.pt            # [N,300] 名称单位向量
    ├── W_a_name_unit.pt            # [M,300]
    ├── W_o_K.pt                    # [N,300] 对象知识向量，当前 C/E 消费
    ├── W_a_K.pt                    # [M,300] 属性知识向量，当前 C/E 消费
    ├── W_ao_K/
    │   ├── obj_00000.pt            # [M,300] 首个对象的全部属性模板向量
    │   └── ...                     # 共 N 块；当前 MVP 不直接读取
    ├── K_oa_text_raw.pt            # [N,M] 原始 template cosine
    ├── K_oa_text_template.pt       # [N,M] template 归一化候选
    ├── K_oa_text.pt                # [N,M] 实际选择的 prior_source
    ├── K_oa_prior_centered.pt      # [N,M] 全局中心化/标准化后的校准项
    ├── report.json
    ├── knowledge_coverage_report.json
    ├── manifest.json
    └── cache_manifest.json         # 与 cache manifest.json 内容相同
```

K 的第一维为对象、第二维为属性，即 `K[obj_index, attr_index]`；不能因为名称里有 `oa/ao` 就反转矩阵。模型按评价候选的对象/属性索引取 prior，candidate 顺序与标签 hash 一并保留。

上述形状来自 builder/model 的合同，报告汇总器不导入 torch、不重新加载张量内容。真正的模型初始化已有标签/形状/消费文件 hash 检查，既有 smoke 及 cache verify 日志另存为证据。

## 5. 原始描述如何变成训练输入

1. **名称向量**沿用现有 CPF 的类别名别名与 GloVe 初始化逻辑；保存 raw 与单位向量，保留 300 维。
2. **描述向量**按 builder 的 regex 分词，仅对 GloVe 内词取平均，随后 L2 归一化；句子没有可用词向量时回退到名称向量。记录 token OOV 比例与 fallback 句子数。
3. **原语知识向量**对“名称单位向量 + 三条描述单位向量”取平均，再 L2 归一化，得到 `W_o_K`、`W_a_K`。保留同一 GloVe 编码器，未换成 CLIP text encoder。
4. **模板候选**对所有 N×M pair 采用同一组三个模板：`a {object} that is {attribute}`、`the {attribute} {object}`、`{attribute} appearance of {object}`。构建模板组合向量并与 `normalize(W_o_K + W_a_K)` 取 cosine，保存 raw，再全矩阵 min-max 得到 template K；退化常量候选设为0.5。
5. **校准项**为 `P=(K−mean(K))/std_population(K)`，总体 std 使用 `unbiased=False`。std<1e-8 时 P 全为0。当前校准分数是 `score + lambda * P[obj,attr]`；lambda=0 时不产生校准改动。

cache `manifest.json` 的 `prior_source` 决定 `K_oa_text.pt` 实际装了哪一种 K。源文件 `K_oa_text_lexical.csv` 的公式是 `0.75*TFIDF_word_cosine + 0.25*TFIDF_character_trigram_cosine`，它与 GloVe template K 是不同候选；默认当前路线用 template，最终报告仍检查实际 manifest。不要把 lexical 的 min/max/std 填入 template K 的统计表。

这些 K 都是文本相似度候选，并非已标定的现实可行性概率。没有 LLM feasibility 时不虚构 LLM-only/mixed 消融。

构建代码读取 split 列表用于获取与核对标签顺序、统计覆盖；语义分数公式不使用 pair 的 train/val/test 归属。不将 train/val/test pair 并集视为兼容度标签，也不使用 test 指标选模板或 lambda。

## 6. A/C/D/E 实际用了哪些知识

| 变体 | 原语文本路径 | 校准路径 | 当前未执行的部分 |
|---|---|---|---|
| A | 现有 CPF 名称向量 | 关闭 | OI 图传播、完整逻辑/特征损失 |
| C | 固定 `W_o_K`、`W_a_K` 进入既有 CPF 网络 | 关闭，lambda=0 | 同上；不直接消费 pair block |
| D | 现有 CPF 名称向量 | 加中心化 K，旧实验 lambda=0.1 | 同上 |
| E | 同 C | 同 D | 同上 |
| Dpost/Epost | 固定 A/C checkpoint | 扫网格，不重新训练 | 与重训 D/E 分开报告 |

因此 C−A 可以描述为“当前聚合文本知识路径相对名称输入的收益”。不能写成“全部 OI/OE/AE 逻辑图已经验证有效”或“随机语义图产生收益”。当前 stage 与未来 USG 随机语义图路线明确分开。

## 7. 报告里必须保存的对应关系

```text
训练 run 的 knowledge_manifest_sha256
        ↓ 与当前 cache_manifest.json 对照
cache input_sha256 的原始源文件路径与 hash
        ↓ 按冻结 hash 核验
OI/OE/AE + 标签列表 + source manifest + review_status
        ↓ 与 builder 配方、cache 文件声明共同记录
模型真正消费的 W_o_K/W_a_K 或 centered K
        ↓
同一 phase/setting/checkpoint 的指标与错误案例
```

新版汇总输出 `tables/knowledge_structure.csv`、`knowledge_schema.json`、`evidence/knowledge_source/` 和本说明。找不到冻结源目录时，使用真实源文件父目录的 `--knowledge-root`；只有字节 hash 匹配才接受，不修改旧缓存来“通过检查”。

报告应写明：结构覆盖核验状态；bulk trust/人工审核程度；源文件与训练缓存是否匹配；OOV/fallback；所选 K 的 shape/min/max/mean/population_std/zero_fraction/quantiles；top/bottom pair 语义抽检。已保存的 cache report 有统计时直接引用，没有的字段标待补。
