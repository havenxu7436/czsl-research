## 4. 为什么最近的条件 head 不能直接算 G/H

| 项目 | 0601 中的 G/H | 最近 `G_K/G_name` |
|---|---|---|
| Text K | 开启 | 冻结的 C_text 底座已开启 |
| Compatibility prior | 开启 | 关闭，λ=0 |
| Pair 文本 `W_ao_K` | 推荐进入 factorized head 的 `pair_bias` | 没有直接读取模板 pair block；使用对象/属性各自的向量 |
| 特征模块 | factorized 或 chunk-wise scoring，嵌入 CPF 训练链 | 外挂 32 维 Generic 条件残差 |
| 总训练损失 | composition＋attribute＋object；H 再加 logic | 只训练新 head 的未混合条件属性 CE |
| 原 CPF 的可训练模块 | 保持原训练策略，联合训练所规定的模块 | 底座全冻结、缓存特征训练 |
| Logic | G 无，H 有 | 均关闭 |
| 读出 | 方案规定的 pair scoring＋prior | 保持底座对象边缘，75% 原条件概率＋25% head 概率 |

25% 混合和固定对象边缘是后来增加的修正，不是 0601 的默认实现。所以这些探索具有复用价值，但不能填进原方案 G/H 的空位。特别是 H 中的四组件联合反传还没有做过。

源码也有直接证据：[服务器 MVP 的 kcc_cache.py](C:/Users/llenovo/Documents/ChatGPT/CZSL/output/BF_conditional_preflight_20261009/extracted/bf/source/models/kcc_cache.py:26) 对 `kcc_feature=true` 仍抛出 `NotImplementedError`。因此，开启旧配置中的 feature 开关不会自动得到 G/H，必须实现相应模块和训练接口。

## 5. 如果只为完成复现，下一步怎么排

### 第一步：固定一个“0601 复现版”协议

先按原方案 §5.3 的单数据集单 seed 范围，选择 UT、seed 3351，优先延续既有 B/F 训练协议：原 CPF/GloVe、原 split 和评价器、10 epoch、统一按 VAL CW AUC 选 checkpoint。校准组 λ=0.1；逻辑组 β=0.01、q=3。这些是已有工程的可复用配方，不声称原指南唯一指定了这些参数。

写清两个知识来源：旧 v1 文本/prior 缓存；B/F 的重建 logic bank。原方案没有要求沿用这两套资产，这里是为了复用已执行对照作出的工程选择。如果改为一套统一的新知识库，必须按新版本重新建立所有相关对照，不能把旧结果直接搬过来。

复现版应明确：固定预算跑完，收益为零或负数仍导出全部结果；非有限数值、接线错误、资产错配属于需要修复的执行问题。历史所有性能/知识 gate 保留原记录，新的完成目标另行登记。

### 第二步：实现原方案的 feature-level head

优先采用 §6.1 的 factorized 实现：属性视觉—知识分数、对象视觉—知识分数、模板 pair embedding 经 MLP 得到的 pair bias。核对当前 CPF 实际特征形状后接入，按对象分块处理 pair 项，避免在 MIT/C-GQA 上构造大尺寸 feature 张量。

原方案示例假设 `v_attr=[B,M,D]`、`v_obj=[B,N,D]`；现有 CPF 接口并非自动满足这一形状。需要明确特征投影/展开方法、组合分数融合方式和是否重复计入对象项，再记录为实际实现。这属于把设计指南落实为工程的必要工作。

接入 §9 的完整训练链：组合 CE、GT-object 条件属性 CE、对象 CE，H 加三项逻辑损失；保持原 CPF 的骨干冻结/可训练策略。当前冻结缓存训练不能替代这一步。H 的属性逻辑 score 是否使用原生属性 head，或采用 §7 推荐的对象边缘化属性 score，也必须固定并记录；不能只有示例类名而没有实际 forward。

### 第三步：补齐 C_ref/D_ref/G/H

保持统一预算和相同基础参数初始化，保存有效配置、逐轮训练/验证指标、知识与源码哈希、最佳权重和 CW/OW 结果。模块关闭应能够回到对应参考分数，并核验 H 的逻辑梯度进入预期可训练模块。

若沿用现有 10 epoch 协议，条件满足时核心缺口是**四次完整训练**，不是当前小 head 的每轮两三秒训练；耗时应以原 CPF 实测为依据。

最终报告比较 H−A、H−B、H−F、G−E、H−G，无论差值是否为正均填写。这些比较完成，即完成原方案的核心问题检验；不需要寻找能让所有不等式成立的新配方。

### 第四步：补齐五项 sanity checks

| 原方案检查 | 已有基础 | 补完方式 |
|---|---|---|
| Shuffled descriptions | C_text/C_shuffle 多 seed、新 head 两套错配均已完成 | 原 G/H 实现后做该架构对应的固定打乱；旧结果作补充，不能自动替代完整模型的控制 |
| Random K_oa | 当前没有找到正式随机矩阵评价结果 | 锁定随机矩阵生成 seed、尺度和 λ，与真实 prior 同口径评价 |
| Uniform K_oa | builder 检查常数矩阵经 centered 变换为零 | 在真实模型/候选评分中确认与关闭 prior 回放一致并保存结果；不必为恒零 prior 重训完整模型 |
| Template-only W_ao | 已有全候选模板 block | G/H 主实现如果直接使用该模板库，主 run 就是 template-only；无需凭空新增 pair LLM 文本做重复比较 |
| No-pair-knowledge | 当前 head 不消费 pair block，但架构不等价 | 在已实现的 factorized G/H 内只关闭 pair embedding 分支，保留原语知识、其余训练设置相同，完成对应消融 |

输出端 random/uniform prior 的固定权重替换可先只做推理，说明它回答的是读出敏感性；如果报告训练中 prior 的作用，再补从初始化训练的对照。不能把推理替换记作独立训练。

### 第五步：形成交付报告

最小核心交付应包括：单数据集单 seed 的同协议 A–H 主表、五项 sanity checks、知识来源/实际实现差异、训练命令、配置与权重身份、所有正负结果。

模型配置和 VAL 选模锁定后，补这一套方法的对应 TEST 结果，形成可交付的最终性能表。早期 CPF TEST 已被查看，应如实记录；没有新增模型 TEST 的事实不能写成“整个项目从未访问 TEST”。原方案没有硬性指定三 seed 才算 §5/§6 跑通，多 seed 确认属于后续证据范围，不能拿它替代眼下缺失的 G/H。

## 6. 哪些是完整分析扩展，哪些不必卡住核心复现

原方案 §11 列出的知识质量、噪声、数量、深度与失败分类可在核心模型跑完后补。若目标包括复现整份分析目录，当前还缺：

- 正式的知识删除/替换 10/30/50% 敏感性实验。
- 每类 1/3/5 条描述的敏感性实验；当前主要用三条，不能把固定三条算作数量消融。
- OI 深度 1/2/3 的系统比较；现有固定父类分组只是一种深度。
- 在完整模型上统一归因 object error、conditional attribute error 与 prior 改动错误；已有逐图分析可复用，但不能自动确定错误的因果来源。
- 如果实际获得 LLM feasibility，再做 text-only/LLM-only/mixed K；原 §4.5 已允许无 LLM 时直接采用 text-only，所以这不是最小复现的先决条件。
- MIT/C-GQA 的完整 A–H 扩展：目前只做过两数据集 A/C，没有 B/D/E/F/G/H 统一结果。原文首先要求单数据集单 seed 起跑，若要覆盖三数据集完整版，必须扩展这些缺项。

`clamped log prior`、marginalized 属性 loss、learnable λ、delayed logic schedule 是原文建议或备选。没有运行对应比较就注明未做；纯复现不要求把每个可选实现全部组合搜索。§11 的 cross-benchmark protocol transfer 明确为可选。

不需要为了完成 0601 而先更换视觉骨干、设计随机语义图、让冻结 CLIP 教师超过名称或再写一批描述。最近的 CLIP 探针和 TRAIN 知识审查是后续研究诊断；其中部分工具包已交付不表示服务器训练已执行，也不占原 A–H 配置的完成名额。

## 7. 如何定义“复现完成”

可以把完成标准写成三个层级，而不给缺乏依据的百分比：

1. **MVP 复现完成**：A–F 工程均有执行结果；目前方法身份已经具备，尚需统一同协议主表。
2. **0601 核心实验复现完成**：补齐 G/H，统一 A–H，完成 §10.3 五项 sanity checks，交付配置、命令和全部结果。是否改善指标不影响这个状态。
3. **0601 完整分析目录完成**：在核心之外补 §11 要求覆盖的敏感性、知识质量和错误分析，以及明确选定的数据集/seed 范围。

原文 Gate 1/2 是根据性能决定是否继续投入的研究规则。若按原规则止步，应该报告“执行了某阶段，推进条件未获得充分支持”；若当前目标是把整套设计跑全，则在新复现协议中明确继续到 G/H，保留原 gate 与负结果即可。不能把完成度和研究假设是否得到支持合并为一个状态。

这次最应该补的具体缺口是：**原方案 factorized/pair-knowledge head → G/H 联合训练 → 同协议 A–H 主表 → 五项 sanity checks。**
