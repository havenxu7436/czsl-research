## 2. Linux 服务器：查看报告并冻结缓存

```bash
(
    set -euo pipefail
    conda activate cpf
    ROOT=/data/xhw/czsl_repro
    PROJ="$ROOT/src/KCC0601_v1"
    CACHE_ROOT="$ROOT/knowledge/kcc0601_v1/cache_trusted_v1"
    EXP="$ROOT/experiments/kcc0601_glove_mvp_v1"

    for ds in ut-zap50k mit-states cgqa; do
        python "$PROJ/tools/build_knowledge.py" \
            --output-dir "$CACHE_ROOT/$ds" --verify-only
    done

    python - "$CACHE_ROOT" <<'PY'
import json, sys
from pathlib import Path
root=Path(sys.argv[1])
for ds in ('ut-zap50k','mit-states','cgqa'):
    r=json.loads((root/ds/'report.json').read_text(encoding='utf-8'))
    print('\nDATASET:',ds)
    for key in ('prior_source','knowledge_status','raw_template_K',
                'K_oa_text','centered_prior','template_K_degenerate',
                'template_K_near_constant_std_lt_1e-4',
                'description_OOV_fraction','description_fallback_sentences',
                'split_coverage_audit_only','top_bottom_pairs'):
        print(key, json.dumps(r[key],ensure_ascii=False))
PY

    mkdir -p "$EXP/protocol" "$EXP/audit"
    stamp=$(date +%Y%m%d_%H%M%S)
    find "$CACHE_ROOT" -type f -print0 | sort -z | xargs -0 sha256sum \
        > "$EXP/protocol/cache_trusted_v1_${stamp}.sha256"
    echo "Frozen cache checksums: $EXP/protocol/cache_trusted_v1_${stamp}.sha256"
)
```

判断重点：原始 cosine 的 std，而不是只看 min-max 后 std；top/bottom pair 是否只是词形重合；描述回退是否集中在特定 split。标准化后的 prior 应有限、均值接近0、总体 std 接近1（常数 K 时应全零）。这些检查支持继续做诊断实验，不能直接证明知识有效。

不要覆盖当前 cache。修订知识或公式时使用新 cache 目录和新实验目录。

成功会看到 `KCC MVP INSTALLED` 与备份目录。安装器检查实际源码锚点后生成覆盖方法；源码不匹配时在写入前报错。已有文件被改动前保存到 `kcc_mvp_backup_<时间>`，其中 `changes.diff` 可直接审阅。

具体影响：

| 文件 | 改动 |
|---|---|
| models/ddm.py | 保留原始基线，供继承和一致性检查 |
| models/kcc_cpf.py | 从服务器实际 ddm.py 生成 composer、train、augment、val 覆盖方法 |
| models/kcc_cache.py | 冻结缓存、标签顺序、SHA、原名称向量一致性检查；按 pair 索引校准 |
| train.py / test.py | 模型导入切换到 kcc_cpf；train 最后 test 加配置开关 |
| tests/smoke_mvp.py | 真实 batch 的基线/梯度/顺序验收 |
| tools/make_mvp_configs.py | 从历史 train.log 的有效配置创建 A/C/D/E，使用 cache_trusted_v1 |
| tools/run_mvp.sh | 保存源码、配置、日志、checkpoint，训练后仅计算 val CW/OW |
| tools/eval_mvp.py | CPU/memmap 保存评分，输出 metrics.json，检查训练时绑定的缓存 |

这个版本支持 A/C/D/E。B/F/G/H 和 conditional score 尚未实现；启用它们会明确报错，避免输出名为 Full Model、实际缺少模块的结果。

模型保持原损失权重和温度。D/E 的 train composition logits 在 CE 前加 prior，val 最终 pair score 加 prior。这仍是主手册中的 legacy 协议；原训练温度与推理 unscaled cosine 的差异保留。缓存使用非持久 buffer，不增加 optimizer 参数，旧 checkpoint 可以 strict load；重新训练时将 cache manifest 单独绑定到 run。

## 5. Linux 服务器：UT 真实 batch 验收

先用 `nvidia-smi` 选择当前空闲物理卡，下面 `GPU=0` 只是示例，按实际空闲卡编号修改。

```bash
(
    set -euo pipefail
    conda activate cpf
    ROOT=/data/xhw/czsl_repro
    PROJ="$ROOT/src/KCC0601_v1"
    EXP="$ROOT/experiments/kcc0601_glove_mvp_v1"
    CACHE_ROOT="$ROOT/knowledge/kcc0601_v1/cache_trusted_v1"
    GPU=2
    CK_Z="$ROOT/runs/cpf_ut_zappos_seed3351/checkpoints/ut-zappos-czsl_final_predcition_mul/best_auc.pth"

    cd "$PROJ"
    test -s "$CK_Z"
    mkdir -p "$EXP/audit"
    CUDA_VISIBLE_DEVICES="$GPU" python tests/smoke_mvp.py \
        --cfg "$EXP/configs/mvp_ut-zappos_A_legacy_s3351_l0.yml" \
        --checkpoint "$CK_Z" --cache "$CACHE_ROOT/ut-zap50k" \
        --out "$EXP/audit/smoke_mvp_ut_s3351.json" --batch-size 2 \
        2>&1 | tee "$EXP/audit/smoke_mvp_ut_s3351.log"
)
```

必须看到最后一行 `MVP SMOKE PASSED`，并有 JSON 结果。测试内容包括：

- 原 checkpoint 在 A 中 strict load；CW/OW 分数最大差 ≤1e-6、Top1 一致。
- A 的训练损失与原始模型一致。
- λ=0 不改分数；全零 centered prior 不改分数。
- D/E 的先验按 `[obj,attr]` gather，反转 candidate 顺序后对应 pair 分数一致。
- A/C/D/E 真实 train batch 的 loss / backward 有限，有非零梯度；知识张量冻结。
- 训练 composition CE 的先验位置及原 0.4/0.6 辅助损失权重正确。

脚本使用一个真实 train batch、一个真实 val batch，不输出 test 成绩。这是实现验收，不是完整数据集精度复评。失败时保留 log，先修实现再训练。重新执行时换一个 JSON 输出文件名，脚本会拒绝覆盖已有结果。

## 7. 查看和比较验证集结果

```bash
ROOT=/data/xhw/czsl_repro
EXP="$ROOT/experiments/kcc0601_glove_mvp_v1"

python - "$EXP" <<'PY'
import json,sys
from pathlib import Path
root=Path(sys.argv[1])
rows=[]
for setting in ('cw','ow'):
    found={}
    for v in ('A','C','D','E'):
        lam='0.1' if v in ('D','E') else '0'
        p=root/'runs'/f'mvp_ut-zappos_{v}_legacy_s3351_l{lam}'/f'eval_val_{setting}'/'metrics.json'
        if not p.is_file():
            print('INCOMPLETE:',p)
            continue
        found[v]=json.loads(p.read_text())
    if 'A' not in found:
        continue
    base=found['A']['metrics_raw']
    for v,r in found.items():
        m=r['metrics_raw']
        row={'setting':setting,'variant':v,
             'AUC_pct':100*m['AUC'],'HM_pct':100*m['best_hm'],
             'delta_AUC_pp':100*(m['AUC']-base['AUC']),
             'delta_HM_pp':100*(m['best_hm']-base['best_hm'])}
        rows.append(row)
        print(json.dumps(row,ensure_ascii=False))
if rows:
    import csv
    dest=root/'audit/mvp_val_comparison.csv'
    with dest.open('w',newline='',encoding='utf-8') as f:
        w=csv.DictWriter(f,fieldnames=list(rows[0]));w.writeheader();w.writerows(rows)
    print('CSV:',dest)
PY
```

比较 C−A（文本增强），D−A（纯校准），E−C（在知识 embedding 上增加校准），E−D（在校准上增加知识 embedding）。K 的均值/方差不能代替这些对照结果。

这里的百分比换算按当前 evaluator 的 [0,1] 指标执行，增益为百分点。报告缺失时标 INCOMPLETE，不当作0分。首轮 seed3351 只用于工程筛查；正式结论仍需要多 seed、负对照、全三数据集与原计划的逻辑/特征模块。

## 8. 若 E 不提升，先诊断而非扩张整轮

- C 下降而 D 正常：检查描述噪声、类别名称与描述等权平均、原名称向量范数与知识单位范数带来的尺度差异。后续增加同归一化的 name-only 对照。
- D 下降：查看 prior top/bottom、原始 cosine std，按已声明的 val λ 网格调权重；不要根据 test 成绩修改 K。
- E 的 val CW 上升但 OW 明显下降：优先看 seen/unseen 覆盖、prior 排序与校准权重，不直接宣称提升泛化。

脚本尚未实现 B/F/G/H。A/C/D/E 验收与首轮诊断通过后，再逐步实现三类逻辑损失和图像条件知识模块。新增模块应重复相应梯度与关闭恒等检查。
