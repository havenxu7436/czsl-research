## 3. 服务器终端：先生成 UT-Zappos

以下整块在 Linux 终端执行。括号把错误退出限制在当前命令块，避免更改当前 SSH shell 的全局退出行为。

```bash
(
    set -euo pipefail
    conda activate cpf

    ROOT=/data/xhw/czsl_repro
    PROJ="$ROOT/src/KCC0601_v1"
    KROOT="$ROOT/knowledge/kcc0601_v1"
    TRUSTED="$KROOT/trusted_v1"
    CACHE="$KROOT/cache_trusted_v1"
    SRC="$KROOT/draft/kcc_logic_3datasets_reconstructed_v1"

    test -f config/ut-zappos.yml
    test -s "$ROOT/data/glove/glove.6B.300d.txt"
    test -s "$TRUSTED/ut-zap50k/oe_dict.json"

    python "$SRC/scripts/validate_server.py" \
        --data-root "$ROOT/data" \
        --knowledge-root "$TRUSTED" \
        --datasets ut-zap50k \
        --require-reviewed

    python tools/build_knowledge.py \
        --project-root "$PROJ" \
        --cfg "$PROJ/config/ut-zappos.yml" \
        --data-root "$ROOT/data/ut-zap50k" \
        --knowledge-dir "$TRUSTED/ut-zap50k" \
        --output-dir "$CACHE/ut-zap50k" \
        --glove-file "$ROOT/data/glove/glove.6B.300d.txt" \
        --encoder glove \
        --descriptions-per-class 3 \
        --pair-mode template \
        --prior-source template \
        --knowledge-status bulk_trusted_unverified \
        --seed 91001
)
```

这里 `--require-reviewed` 只检查 CSV 的 `approved` 字段，你此前选择的批量信任可以通过它。缓存会继续明确记录 `bulk_trusted_unverified`，不会把字段通过解释成人工逐项复核。

GloVe 会被完整扫描一次以计算 SHA256；仅把需要的词向量保留在内存中。计算使用 CPU，不需要占用 GPU。程序不会创建训练进程。

## 4. 服务器终端：验证输出并阅读报告

```bash
ROOT=/data/xhw/czsl_repro
PROJ="$ROOT/src/KCC0601_v1"
CACHE="$ROOT/knowledge/kcc0601_v1/cache_trusted_v1/ut-zap50k"

import json

r = json.loads((p / 'report.json').read_text(encoding='utf-8'))
for key in ('prior_source', 'knowledge_status', 'raw_template_K',
            'K_oa_text', 'centered_prior', 'template_K_degenerate',

```

`--verify-only` 会复核输出文件以及源数据、知识文件、GloVe 的 SHA256。它会再次读取 GloVe，因此有一定磁盘读取时间。

输出目录结构：

```text
cache_trusted_v1/ut-zap50k/
├── W_o_K.pt                       # 12 × 300，单位范数
├── W_a_K.pt                       # 16 × 300，单位范数
├── W_o_name_raw.pt                # 原初始化器语义的名称向量，保留尺度
├── W_a_name_raw.pt
├── W_o_name_unit.pt               # name-only 控制用，单位范数
├── W_a_name_unit.pt
├── W_ao_K/
│   ├── obj_00000.pt               # 每对象 16 × 300
│   └── ...
├── K_oa_text_raw.pt               # 模板 embedding 与 prototype 的 cosine
├── K_oa_text_template.pt          # 全局 min-max 归一化后模板 K
├── K_oa_text.pt                   # 本次选择的 K；默认同 template
├── K_oa_prior_centered.pt         # 全局总体标准差标准化后的 prior
├── labels.json
├── manifest.json
├── cache_manifest.json            # 同 manifest，兼容主手册命名
├── report.json
└── knowledge_coverage_report.json # 同 report，兼容主手册命名
```

重点看：

- 标签顺序是否通过检查；不是只验证矩阵大小。
- `template_K_degenerate` 是否为 false。常数或数值退化 K 会保存成中性 0.5，centered prior 会全零，应暂停对该 K 的有效性解释。
- 原始 cosine 的 std，而不只看归一化后 std；min-max 可以放大微小差异。
- 描述 OOV、回退句子数量、各 split 的回退比例，以及 top/bottom pair 是否合理。模板覆盖率为 1 只说明所有 pair 都生成了向量，不说明知识语义已验证。

向量构建规则已写入 manifest：保持现有类别名称 alias；描述按 token 取同一 GloVe，忽略 OOV 并记录；句子无可用向量时回退到该类名称；逐句 normalize、名称与描述等权平均、再次 normalize。名称 OOV 直接报错，避免随机补向量。

pair 使用统一三模板，覆盖完整对象×属性 Cartesian product。K 使用设计中的公式：

```python
proto = normalize(W_o_K[o] + W_a_K[a])
K_raw[o, a] = cosine(W_ao_K[o, a], proto)
```

再对完整矩阵做 min-max，最后运行 `centered_prior()`。split 成员关系只用于标签和覆盖率报告，不参与 K 分数生成。

```bash

            --output-dir "$CACHE/$ds" \

            --pair-mode template --prior-source template \
            --knowledge-status bulk_trusted_unverified --seed 91001

```

预期尺寸：

| 数据集 | W_o_K | W_a_K | K |
|---|---|---|---|
| ut-zap50k | 12 × 300 | 16 × 300 | 12 × 16 |

## 6. 常见报错与后续接口

- `No such file ... build_knowledge.py`：检查上传目标，需为项目的 `tools/build_knowledge.py`。
- `ModuleNotFoundError: torch/yaml/torchvision`：先 `conda activate cpf`，核对 `which python`；本步骤沿用原训练环境。
- `source has pending entries`：检查 `--knowledge-dir` 是否误写成 `reviewed_v1`，本轮使用你已处理的 `trusted_v1`。
- `label ... order mismatch`：实际 dataset 与知识标签不一致；停止接入模型，不要靠重排 K 的数字蒙混通过。
- `baseline name OOV`：当前初始化器 alias / GloVe 版本需要核对，不能随机补向量。
- `cache already exists`：脚本拒绝覆盖已有缓存。如果只是验证，用 `--verify-only`；若确实修订协议，指定新目录，如 `cache_trusted_v2`，并修改对应模型配置。
- `template_K_degenerate=true`：常数先验不提供校准作用；应查看公式/向量统计后另建协议版本，不能宣称通过标准化得到了兼容性。

若需要保留现有词形 CSV 作为单独诊断，将构建命令的 `--prior-source template` 改为 `--prior-source lexical`，同时将输出目录改为 `cache_trusted_lexical_v1/<dataset>`。该版本记录为 lexical 候选，不是 LLM feasibility。
