## 0. 使用范围与执行顺序

这份手册基于你的三套 CPF 结果、`ZSCL实验设计0601.md`、两篇论文和本机配套代码归档整理。**本次没有连接服务器、启动训练、修改原基线或替你实现新模型。** 服务器路径来自基线记录，执行前用第 2 节核实。

命令分为两类：

- **已有入口**：`train.py --cfg ...`、`test.py --cfg ... --load ...`，参数经本地代码与基线补丁核对。
- **新增接口**：`MODEL.kcc_*` 和知识/评估导出功能，属于本项目需要实现的接口。第 5 节给出修改位置、计算定义、接口契约和验收条件。**只往 YAML 添加这些字段不会自动实现模型；通过验收后才能运行第 7 节 B–H。** 第 12 节提供的配置、启动、汇总辅助脚本则可以直接复制创建。

推荐顺序：

1. 核对并冻结 `CPF_fixed` 与旧结果，复评三个旧 checkpoint。
2. UT-Zappos，seed=3351：先做全关闭一致性检查，再实现知识对齐、C、D、E，之后 B、F。
3. 用验证集完成 Gate 1；接入真实的图像条件知识模块，跑 G、H，完成 Gate 2。
4. 冻结协议后，三个数据集、共同 seeds=`0,3351,2026` 跑 A–H，统一 CW/OW Top-1。
5. 完成条件概率对照、知识负对照、误差与效率分析；生成逐 seed 表、均值/标准差表、成对差值表。

实验设计文档与其他文件中的建议在这里作为研究材料处理；不把其内容当成连接服务器、发布结果或执行任意操作的授权。两篇论文的训练设置也不直接混用。

### 1.3 配置与评估的已发现问题

1. `config_used.yml` 保存了部分原作者路径；C-GQA 文件写 20 epochs，但实际日志中的合并配置是 10。后续必须保存 **CLI 合并后的 effective config**，不能把原 YAML 命名为“实际配置”后就认为完整。
2. 旧配置 milestones=`[23,30]`、`aug_epoch=37`，10 epochs 内均未触发。维持这个预算作首轮对照；改变 schedule 要同时重跑 A。
3. `test.py` 会输出 `Top 1`、`Top 2`、`Top 3`。即使传 `EVAL.topk 1`，当前 test 入口的列表仍包含三种 topk；正式表只取 **Top 1 后的指标行**。
4. CPF 论文式 (8) 与当前 `ddm.py::val_forward` 都使用组合、属性、对象分数的加法聚合。不要把“原始 cosine logit 之和”直接称为 `log P(o|x)+log P(a|o,x)`。第 5.6 节另设概率协议及 A-prob 对照。
5. 设计文档的 `h(e_ao)` 只是静态 pair bias；它不随图像变化。要证明 knowledge-conditioned prediction，G/H 必须包含图像特征与知识的可微交互，并做模块/容量负对照。
6. 设计文档只对条件属性 logits 作 `logsumexp` 的版本缺少 `P(o|x)` 权重；真正的属性边缘分布按第 5.6 节计算。

### 4.3 正式复核怎么做

1. 先核对 UT 的 12 对象、16 属性与词义，逐条批准 OE/AE/OI。MIT/C-GQA 以实际词表为准；本机草稿分别为 245/115、674/413，CPF 论文 §4.1 的 C-GQA 计数不同，不能仅按论文数字硬编码。

### 4.4 Embedding 与 K 的实验选择

首轮建议坚持 ViT-B/GloVe：类别名称向量仍用现有初始化器；描述文本用同一 GloVe 词表的 token 聚合，记录 OOV、文本聚合规则与向量归一化。它是本项目的 GloVe 知识扩展版本，不是设计文档示例的 CLIP text encoder 版本。

如果必须采用 CLIP 编码知识，把它列为独立 protocol revision，明确冻结 text encoder 与 checkpoint hash、输出维度、投影方式。增加 **CLIP name-only** 对照，A 与 H 保持相同视觉 backbone；若改成 CPF-CLIP，则单独完整重跑该路线 A–H，不能与当前 ViT-B 结果拼表。不要将 512/768/1024 维向量直接覆盖 300 维 embedding。

K 构建：先实现设计文档的 template/text similarity 版本，检查是否近常数、是否仅反映词形。所有 `N×M` pair 使用一致模板，不使用 pair split 身份。若无 LLM feasibility，只保存 `K_oa_text`；不虚构 LLM-only/mixed 消融，不把缺失 LLM K 设零再混合。

centered prior 使用总体标准差：

```python
def centered_prior(K, eps=1e-8):
    K = K.float()
    if not torch.isfinite(K).all():
        raise ValueError("non-finite K")
    std = K.std(unbiased=False)
    if std < eps:
        return torch.zeros_like(K)  # uniform sanity：常数先验贡献必须为零
    return (K - K.mean()) / std
```

正式 prior 候选至少报告 min/max/mean/std、零值比例、分位数、top/bottom pair 语义抽检、seen/unseen覆盖率、mask率；prior质量不是只看矩阵形状。以验证集 D 对照判断其用途，不能用 test 是否提升选 K。

### 5.4 MVP 在哪些位置接入

`models/kcc_cpf.py` 是复制自实际 `ddm.py`，两个 forward 都要修改，不能只改训练。

| 修改点 | 实际锚点 | 操作与要求 |
|---|---|---|
| Text K | `_setup_word_composer`、`self.obj_embedder/attr_embedder` | cache label逐项对齐；对启用文本的模型统一替换/融合；名称词不被随机shuffle |
| Visual TEO | `obj_weight`、`choose_texts(vis_obj,obj_weight)` | 接收对应 W_o_K；保留其它attention算法 |
| Composition文本 | `compose_word_embeddings` | 明确该 composer 是否也使用知识向量；C/E/F/G/H统一 |
| Calibration | val forward 最终 `pred` 与 train forward 的 `comp_pred` | 对所有训练/评估候选按 `(attr,obj)` gather prior，不取argmax object一行 |
| Logic | train forward 最大值索引前的原始 logits | 从 object/attr/node raw logits计算loss，不能将class index送入 |
| Loss | `loss = comp_loss + 0.4*obj_loss + 0.6*attr_loss` | 主A–H保持原权重，beta只乘一次；禁用的新项严格为零 |

MVP主A–H采用 `legacy` 评分：保留原模型loss与分数组合，仅添加经定义的知识项。可把原 train `comp_pred` 的 calibration加在其CE之前；val加在最终score之后。其训练/推理原有温度差异须记录，不为单个变体偷偷改变。D 的主表版本按此重新训练；**D-post** 可以先对 A checkpoint 只做推理校准，作为廉价诊断，单独命名，不能当成重新训练的 D。

### 5.5 Logic adapter：避免概率重复变换与 beta 重复相乘

本地 `LogiCZSL/models/Troika/model/logicloss.py` 接口是：

```text
[obj_logits(B,N), hc_parent_logits(B,H),
 oda_child_logits(B,N,3), attr_logits(B,M), ada_child_logits(B,M,3)]
```

它内部对 logits 作 softmax，`LogicLoss.forward` 末尾已乘 `0.01`。如果外面再乘 beta=0.01，实际系数变成0.0001；先 adapter.softmax 再送进去也会重复变换。

实现 `models/logic_adapter.py`：使用原文件**未加权**的 `logit_hc/logit_oda/logit_ada` 求和，外部只乘一次 `kcc_beta`。若使用概率形式重写operator，应明确替换整个接口，不能与原softmax版混用。

- OI：object visual/text logits与独立 hierarchy文本节点 logits，mapping=`parent_idx -> [obj_idx,...]`。
- OE/AE：对应视觉特征与固定三描述向量的相似性；尺度/temperature相同。描述无learnable label或GT泄露。
- 第一轮 q=3、beta=0.01；只OI的debug先命名 B-oi，**不能记作B全三逻辑**。
- log训练中的 `loss_com/loss_obj/loss_attr/loss_oi/loss_oe/loss_ae/beta_t/weighted_logic`，每项都保存，不只保存 total。
- 如果采用不同逻辑实现，B/F/H必须统一同一 adapter与描述分类规则；“naive combination”对照要尽可能忠实移植，偏离处写清楚。

### 5.6 Full Model：真正的条件知识交互与概率协议

对现有实际特征使用 `v_obj=vis_obj_new (B,300)`、`v_attr=attr_emb (B,300)`；**不要假定它们已是 `B×N×D` 和 `B×M×D`**。推荐生成对象条件 query，与pair知识key交互：

```python
# 计算定义；需接入实际模型与已对齐缓存，不是完整可运行训练脚本。
q = normalize(phi_v(v_attr)[:, None, :] + phi_o(e_obj_K)[None, :, :])  # B,N,h
k = normalize(psi_pair(e_ao_K))                                      # N,M,h
r_ao = einsum('bnh,nmh->bnm', q, k)                                 # B,N,M
```

这样 r 随图像x与object o变化，又依赖K；phi/psi可微。不加入另一个重复对象logit项。legacy路线把 residual `eta*r` 加到原pair score；conditional路线把 residual 加入条件属性 c。写两个测试：相同K、不同图像的 residual非恒定；固定图像、打乱K的residual改变，且backward对phi/psi有有限梯度。静态 `h(e_ao)` 可以做 Static-K 消融，但不能作为G/H唯一交互。

**概率路线另设 protocol=`conditional_v1`，必须有 A-prob 对照**：

```python
# 统一温度，并在完整N×M上按attribute维归一化，然后再抽取候选。
log_p_o = F.log_softmax(z_obj.float(), dim=-1)               # B,N
log_p_a_given_o = F.log_softmax(c_ao.float(), dim=-1)        # B,N,M
log_joint = log_p_o[:, :, None] + log_p_a_given_o
score = log_joint + lambda_k * prior[None, :, :]             # soft calibration后的score
log_p_a = torch.logsumexp(log_joint, dim=1)                  # B,M，正确object边缘化

# 训练：CE候选集合只含训练pairs；条件属性辅助loss可用GT object。
scores_train = score[:, train_obj_ids, train_attr_ids]       # 按dset.train_pairs顺序
loss_com = F.cross_entropy(scores_train, pair_labels)
rows = torch.arange(c_ao.size(0), device=c_ao.device)
loss_attr = F.nll_loss(log_p_a_given_o[rows, obj_labels, :], attr_labels)
loss_obj = F.cross_entropy(z_obj, obj_labels)
```

`c_ao` 可以以现有composition cosine与attribute cosine组成的raw条件logits为基础，再加入image-conditioned residual；不能包含已计入的同一个z_obj。该定义必须在 A-prob/F-prob/H-prob保持一致。

calibration后 `score` 不再自动是归一化的log概率；如果报告概率/ECE/NLL，须再对相同candidate集合 `log_softmax(score)`。CW与OW用各自集合，不能混算ECE。属性边缘化若以calibrated joint定义，先重新归一化全joint再边缘化。

条件归一化的分母必须含该object的**全部属性**，不能仅含训练seen属性。CW候选可在最后按标准split mask限制；OW使用完整A×O，不能用test的存在性mask。GT object只用于辅助训练loss/oracle诊断，不用于主推理。

第一轮条件协议最低对照：A-prob、B-prob、E-prob、F-prob、G-prob、H-prob；正式需要分别证明 H-prob>A-prob/B-prob/F-prob，G-prob>E-prob。legacy主表中的增益不能独自证明严格条件概率建模。

### 5.7 C-GQA 内存与 candidate顺序

按本机草稿计数 B=64,N=674,M=413,D=300：`B×N×M×D` FP32仅单个张量约19.9 GiB，还不含梯度、backbone、optimizer；`B×N×M` score约68 MiB。pair缓存 `N×M×D` FP32约319 MiB，CLIP d=1024约1.06 GiB。

按object分块计算 residual与conditional logits；chunk=32起步，OOM则16/8。不能假定chunk就省掉全部训练activation；每个chunk的计算图、pair投影仍占显存。需要验证optimizer+backward峰值，必要时checkpoint/recompute。

## 6. 实验矩阵、调参与停止条件

### 6.1 主实验与必要对照

| 变体 | Text K | soft calibration | image-conditioned Feature K | 三逻辑loss | 含义 |
|---|---|---|---|---|---|
| A | 0 | 0 | 0 | 0 | 同版CPF，原loss与legacy score |
| B | 0 | 0 | 0 | 1 | external logic，判断仅外部正则化 |
| C | 1 | 0 | 0 | 0 | text only |
| D | 0 | 1 | 0 | 0 | calibration参与训练与推理 |
| E | 1 | 1 | 0 | 0 | text+calibration |
| F | 1 | 1 | 0 | 1 | naive full combination |
| G | 1 | 1 | 1 | 0 | image-conditioned feature K |
| H | 1 | 1 | 1 | 1 | Full Model |

每个变体同样的10 epochs、train batch64、test batch64、Adam lr与backbone lr、split、图像增强、validation-best CW AUC选择规则。最终checkpoint同时评CW/OW，不能分别挑两个test最好的checkpoint。

主legacy矩阵：3数据集×8变体×3seeds=**72次训练、144份Top-1 test评估**。不含MVP调参、负对照、条件概率协议。共用seed列表=`0,3351,2026`；历史MIT seed0和另外两组seed3351只有在源码/数据/选择规则等完全一致时才可复用，否则全部新跑A。

条件概率协议：至少A/B/E/F/G/H的conditional版本，在同seeds/数据集逐步补齐；完整三数据集三seed为**54次额外训练**。先UT做定义验收，再决定扩展；不得从legacy表推导未跑的conditional数字。

### 6.2 首轮调参预算（预先写入protocol）

1. UT seed3351，A固定；C、D、E先跑lambda=0.1，B、F初始beta=0.01，eta=0.1，hidden=128，q=3。
2. lambda候选=`0,0.025,0.05,0.1,0.2`；先D-post固定A checkpoint、UT **val** 检查尺度与是否毁掉OW unseen，再对E最多5个训练配置确认。D-post结果不得代替D主表。
3. beta候选=`0.003,0.01,0.03`，最多3个F配置；若logic显著不稳定，再比较固定beta与预定义warmup=2/ramp=2，不无限加搜索预算。
4. G/H首轮不额外搜维度/深度；固定hidden128、chunk32、eta0.1。若要优化eta，候选=`0.03,0.1,0.3`，给所有需要feature的对照相同预算并记录。
5. K_text/K_llm/K_mix定义必须预先冻结；只在有完整可追溯LLM K时增加对应实验。无LLM K就标N/A。

优先用UT确定可迁移的设置；MIT/C-GQA首轮沿用。若允许逐数据集调lambda，在看test前声明同样的候选集合与预算，所有方法的tuning budget入表。不要为H独享更长训练或更多随机seed。

### 6.3 验证集选择及 Gate

MVP/Gate主要依据 **val CW AUC**，次指标val HM；val OW AUC/Unseen作预先声明的退化检查。建议初始预注册：OW AUC退化超过0.5pp或OW best_unseen退化超过2pp进入诊断。这两个阈值是本手册建议的工程阈值，不是论文标准，三seed后应结合波动判断。

| Gate | 通过条件 | 未通过时动作 |
|---|---|---|
| Gate 0 | 旧checkpoint复評通过；A开关恒等；缓存/梯度测试通过 | 修实现/协议，不启动B–H整轮 |
| Gate 1 | A–F跑通；E或F在val AUC/HM至少有一项正收益，另一项无显著退化；OW检查通过 | E不增益则分查C/D；F<E则查beta、adapter与语义；换方案后立新revision |
| Gate 2 | G/H跑通；G≥E、H≥F在预定val指标上无明显下降，feature梯度/动态性证明成立 | 检查过拟合、eta、图像交互是否有效、静态bias是否占主导 |
| Confirm | 三seed同协议、无失败；核心差值均值与每seed结果可审计 | 如实报告负增益或不稳定，不只保留提升seed |

单seed Gate只决定是否值得继续工程，不能作为统计结论。若val失败两轮仍无改进，停止扩张矩阵，记录诊断与新假设；不要靠在test上挑checkpoint救结果。

## 9. 比较、统计和论文证据链

### 9.1 指标解释与主表

使用原evaluator定义：AUC主指标，best HM次指标，best Seen/Unseen辅助。HM=`2SU/(S+U)`必须用**同bias下**的S/U；best_seen和best_unseen通常不是同一点，不能据此重算HM。AUC也不能用四个summary数字重建，需原bias sweep与积分定义。

协议允许在test扫bias报告标准best HM/AUC时，将其明确标作benchmark曲线指标；模型/参数/epoch仍仅val选择。额外报告 **val选定bias在test的HM/S/U** 更能反映部署结果，与test-oracle best HM分开。附录脚本先保留原evaluator指标；val-bias/curve需按真实evaluator实现新增导出，不伪造不存在的值。

逐seed表：dataset×setting×variant×seed→AUC/HM/Seen/Unseen。均值表：同dataset/setting/score_mode/知识版本/训练预算下，mean±sample SD，n=3。同一个run的CW/OW不是两个独立seed样本。

### 9.2 必做成对差值

| 对比 | 支持的结论 |
|---|---|
| H−A | 整体优于同版CPF |
| B−A | external logic的贡献 |
| C−A | 文本扩展贡献 |
| D−A | calibration贡献 |
| E−A | MVP贡献 |
| F−E | logic在MVP上的贡献 |
| G−E | 图像条件feature模块贡献 |
| H−F | 优于naive combination |
| H−B | 优于仅external loss |
| H−G | logic在feature版本上的贡献 |

每seed `delta_pp=100*(metric_H_seed−metric_control_seed)`；保存3个差值、mean、sample SD、正增益seed数。不能H用seed0、A用seed3351去做“成对差值”。

小样本不宣称高置信显著性：n=3可以给基于差值的t区间（df=2，95%临界值约4.303），并注明假设/不稳定。不要仅凭全部三seed正增益宣称统计显著。增加到5seeds用于最终关键H/A/F/G比较更有价值，追加前预声明seed和预算，不能看到失败seed就替换。

图像bootstrap若要做，需要同时保持seen/unseen层、原evaluator的micro/macro与候选协议；它估计测试采样不确定性，与跨训练seed波动不同，不能混算一个SD。

### 9.3 统一对照中的变量

必须同时核对：视觉预训练权重、文本encoder、数据split、候选集合、train样本数、augmentation、epoch/optimizer/lr/温度/AMP、batch和有效batch、validation选择规则、知识来源/覆盖率、参数量、评估版本。新H参数更多时增加等参数capacity control，不把所有增益归因知识语义。

同时报告对论文的gap与对自己baseline的delta；ViT-B表和CLIP表分开，原LogiCZSL-Troika与CPF-B不在“唯一改变logicloss”的同条件表混排。

|---|---|---|
| shuffled descriptions | C/E/H vs对应shuffle版 | 类名保留，只置换类的描述组；保持每组3句、句长分布、encoder和所有参数；固定control seed |
| random prior | D/E/H vsrandom-prior | 用真实K元素的固定随机置换更好，保留边际分布；另可独立随机矩阵并匹配mean/std；重新训练/推理两端一致 |
| uniform prior | E vsconstant-K | centered后全零；同checkpoint推理应与lambda0完全一致；lambda0训练作为对照 |
| template-only | H-pair-LLM vsH-template | 所有pair都有同模板fallback；若当前本来template-only，标本项已是默认，无新结果 |
| no pair knowledge | H vsH-no_pair | 去掉pairK交互，保留obj/attr文本K和同budget；标明容量变化 |
| Static-K | G/H vsstatic-bias版 | 判断image-dependent interaction必要性，不能把static-bias称conditional head |
| capacity control | H vs同参数随机/名称模板key版 | 保留同phi/psi/维度/训练预算，仅替换知识语义 |
| name-only text | text-K vs同encoder名称版 | 排除更换text encoder/归一化/模板本身收益 |

实现control字段后，生成命令例如：

```bash
    cfgpath=$(python tools/make_config.py \
      --root "$ROOT" --exp "$EXP" --kroot "$KROOT" \
```

这些名称在模型/知识控制器实际实现之前不可调用。先单seed检查，最终支持论文结论的关键负对照再补3seeds。随机知识可用3个control seeds检查结论是否依赖一次幸运shuffle，但与training seed分两列保存。

### 10.2 误差分解与失败样本

每图记录image_id/path、GT attr/obj/pair、seen标记、主pair预测、object-only预测、GT-object条件属性预测、with/without-prior预测、GT rank、top5 pair、K值。固定方法A/F/G/H与同seed比对。

- object error：object-only Top-1错误；
- attribute-under-GT-object error：用GT object作为诊断条件仍预测错属性；
- prior flip：同checkpoint关闭/开启prior之后预测变化。分别计“正确→错误”“错误→正确”“错误→另一错误”，这属于受控score干预，不直接称因果归因；
- overlap：object/attribute错误可以重叠，不能把这些率直接相加当100%的互斥分解。

失败样本类别：视觉模糊/遮挡、语义多义、描述错义、知识缺失、prior过强、object传播错误。预先按固定seed抽取seen/unseen成功/失败各25例，保留抽样脚本与全部例子，不只挑H正确的展示。

### 10.3 额外分析的可执行排期

先UT做description count=`1/3/5`（只有生成了5条同质量知识才能做）、noise=`0/10/30/50%`（固定噪声mask）、K来源text/LLM/mix、logic oi/oe/ae组合、GT-object vsweighted-marginalized attr loss。每个设置用独立配置/run_id。只有实际多层OI树存在才做depth1/2/3；当前单层WordNet草稿不能直接用于深度实验。

性能计时：同GPU、相同batch、相同candidate数与精度，至少10 warmup+100计时batch，计时前后 `torch.cuda.synchronize()`；分别报告encoder-only/完整scoring/end-to-end含I/O定义。记录trainable params、峰值allocated/reserved、CPU RAM与磁盘缓存、每epoch时间，不能引用原论文fps替代新模块效率测量。

## 11. 失败恢复、归档与完成清单

| 问题 | 首先检查 | 下一步 |
|---|---|---|
| NaN/Inf | loss分项、K std、softmax/logsumexp、dtype、temperature | FP32 normalization与有限值assert；修后新revision重跑同A |
| OOM | BNM D扩展、eval GPU累积、pair缓存投影图、候选数 | 先chunk32→16→8、CPU memmap、checkpoint；变batch/AMP须重跑匹配A |
| H<F/G<E | feature动态性、梯度、过拟合、eta、静态pair bias | 看val曲线/Static-K/name-only/capacity，不依据test调 |
| F<E/H<G | beta是否双乘、节点softmax、文本错义、loss权重 | 降beta或固定warmup/ramp；保留负结果 |
| OW Unseen骤降 | K范围/scale、candidate误mask、coverage bias | lambda0诊断、shuffle/uniform对照、全A×O检查 |
| strict load失败 | 模型开关与训练cfg、缓存版本、额外buffer | 使用原run完整cfg，不能简单strict=False掩盖 |
| SSH断线 | tmux、进程状态、日志最后时间 | 仍在运行就重连，不重复启动；确认失败后新run |

### 12.3 Top-1评估与JSON输出：支持val/test

`test.py`的既有CLI没有phase参数，不能直接给它传 `--phase val`。此处创建一个独立入口，明确复用相同 dataset/model/evaluator：

```bash
cat > tools/eval_phase.py <<'PY'
import argparse, hashlib, json, re, sys, tempfile, time
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[1]))
import numpy as np
import torch
from config import cfg
from dataset import CompositionDataset
from models.kcc_cpf import DDM
import evaluator_ge

def sha(path):
    p=Path(path)
    if not p.is_file(): return None
    h=hashlib.sha256()
    with p.open('rb') as f:
        for block in iter(lambda:f.read(8*1024*1024),b''): h.update(block)
    return h.hexdigest()

def scalar(x):
    if torch.is_tensor(x): x=x.detach().cpu().numpy()
    z=np.asarray(x)
    return float(z.item()) if z.size==1 else None

def main():
    p=argparse.ArgumentParser()
    p.add_argument('--cfg',required=True)
    p.add_argument('--load',required=True)
    p.add_argument('--phase',choices=['val','test'],required=True)
    p.add_argument('--setting',choices=['cw','ow'],required=True)
    p.add_argument('--out',required=True)
    p.add_argument('--save-scores',action='store_true')
    p.add_argument('opts',nargs=argparse.REMAINDER)
    a=p.parse_args()
    cfg.merge_from_file(a.cfg); cfg.merge_from_list(a.opts)
    assert bool(cfg.EVAL.open_world)==(a.setting=='ow'), 'setting/config mismatch'
    cfg.EVAL.topk=1
    dest=Path(a.out); dest.mkdir(parents=True,exist_ok=True)
    if (dest/'metrics.json').exists() or (dest/'scores.dat').exists():
        raise FileExistsError('refusing overwrite: '+str(dest))
    device=torch.device('cuda:0')
    trainset=CompositionDataset(phase='train',split=cfg.DATASET.splitname,
               open_world=cfg.EVAL.open_world,cfg=cfg)
    ds=CompositionDataset(phase=a.phase,split=cfg.DATASET.splitname,
               open_world=cfg.EVAL.open_world,cfg=cfg)
    dl=torch.utils.data.DataLoader(ds,batch_size=cfg.TRAIN.test_batch_size,
               shuffle=False,num_workers=cfg.TRAIN.num_workers)
    model=DDM(trainset,cfg).to(device)
    model.load_state_dict(torch.load(a.load,map_location=device),strict=True)
    model.eval()
    model.val_attrs=torch.tensor([ds.attr2idx[x] for x,y in ds.pairs],device=device)
    model.val_objs=torch.tensor([ds.obj2idx[y] for x,y in ds.pairs],device=device)
    model.val_pairs=ds.pairs
    ev=evaluator_ge.Evaluator(ds,model)
    n=len(ds); nc=len(ds.pairs)
    print('phase=',a.phase,'setting=',a.setting,'images=',n,'candidates=',nc,
          'score_disk_GiB=',4*n*nc/(1024**3),flush=True)
    truth_a=np.empty(n,dtype=np.int64); truth_o=np.empty(n,dtype=np.int64)
    truth_p=np.empty(n,dtype=np.int64)
    # 标明bias=0的top5，不能冒称best-HM bias预测。
    top5=np.empty((n,min(5,nc)),dtype=np.int64)
    torch.cuda.reset_peak_memory_stats()
    start=time.time()
    with tempfile.TemporaryDirectory(prefix='score_tmp_',dir=str(dest)) as td:
        scorepath=dest/'scores.dat' if a.save_scores else Path(td)/'scores.dat'
        mm=np.memmap(str(scorepath),mode='w+',dtype=np.float32,shape=(n,nc))
        offset=0
        with torch.no_grad():
            for batch in dl:
                for k,v in batch.items():
                    if torch.is_tensor(v): batch[k]=v.to(device,non_blocking=True)
                out=model(batch)
                mat=torch.stack([out['scores'][pair] for pair in ds.pairs],dim=1)
                mat=mat.detach().float().cpu()
                if not torch.isfinite(mat).all(): raise ValueError('nonfinite scores')
                b=mat.size(0); sl=slice(offset,offset+b)
                mm[sl]=mat.numpy()
                truth_a[sl]=batch['attr'].cpu().numpy()
                truth_o[sl]=batch['obj'].cpu().numpy()
                truth_p[sl]=batch['pair'].cpu().numpy()
                top5[sl]=torch.topk(mat,min(5,nc),dim=1).indices.numpy()
                offset+=b
                del out,mat
        assert offset==n
        mm.flush()
        matrix=torch.from_numpy(mm)
        pred={pair:matrix[:,i] for i,pair in enumerate(ds.pairs)}
        ga=torch.from_numpy(truth_a); go=torch.from_numpy(truth_o); gp=torch.from_numpy(truth_p)
        results=ev.score_model(pred,go,bias=1e3,topk=1)
        stats=ev.evaluate_predictions(results,ga,go,gp,pred,topk=1)
        vals={k:scalar(v) for k,v in stats.items() if scalar(v) is not None}
        for required in ['AUC','best_hm','best_seen','best_unseen']:
            if required not in vals: raise ValueError('missing metric '+required)
            if not np.isfinite(vals[required]): raise ValueError('nonfinite metric')
        run=Path(getattr(cfg.TRAIN,'kcc_run_dir',str(dest.parent)))
        best_epoch=None
        if (run/'train.log').exists():
            matches=re.findall(r'Loading validation-best checkpoint from epoch (\d+)',
                              (run/'train.log').read_text(errors='replace'))
            if matches: best_epoch=int(matches[-1])
        meta={
```
