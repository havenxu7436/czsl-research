## 2. 原设计首先要修正的地方

原文件：`C:/Users/llenovo/Desktop/ZSCL实验设计0601.md`。

第 6.1 节示例的核心代码：

```python
z = z_o_aux[:, :, None] + z_a[:, None, :]
pair_bias = self.pair_bias(e_ao_K).squeeze(-1)
z = z + pair_bias[None, :, :]
```

存在两个限制：

1. `pair_bias = h(e_ao_K)` 不读取图像。同一组合在所有图像上增加相同数值，属于可学习的静态组合偏置。
2. 示例中的 `z_a` 沿对象维广播，因此这一项自身不随候选对象变化。是否有对象条件信息还依赖上游特征，不能凭函数名称证明。

因此，直接照抄该示例不能验证“图像、候选对象和知识共同决定属性预测”。如果把完整的对象辅助分数再次叠加到已有联合分数，还要检查是否重复计算对象项。

另一个限制：现有 `build_knowledge.py` 用 GloVe token 平均生成 template pair embedding。它可以作为文本表示基线，但不保证编码语序、否定、属性多义或真实组合可行性。更换为更强编码器时，必须单独建立 protocol revision，并同步重跑对应的文本对照。

## 3. 建议检验的核心假设

> 保留知识的描述条目和关系类型，让图像证据与候选对象共同决定哪些知识参与属性预测；这种条件利用方式，比等量文本聚合、静态组合偏置和仅使用外部逻辑损失更有利于组合泛化。

这是研究假设。普通 attention、FiLM、gate、MoE 都有广泛已有工作，单独采用其中一个组件不能证明新颖性。潜在贡献需要来自明确的关系建模、知识证据的条件使用方式，以及对应的对照结果。

不要把“常见对象属性”当作每张图片都必须成立的硬规则。例如，对象描述中的典型属性不应强迫所有该对象图像都满足它。

### 3.1 与随机语义图路线的边界

本路线命名为 **条件语义规则路线**，`route_id = conditional_semantic_rules_v2`。下表右列是暂定的另一条路线定义，不代表已经检查过用户该路线的具体实现。

| 维度 | 本方案：条件语义规则 | 随机语义图路线的暂定定义 |
|---|---|---|
| 核心问题 | 哪些语义条目在当前图像和候选对象下有依据 | 随机构造/扰动的语义连接如何帮助表征学习 |
| 知识载体 | 描述条目、关系类型、可解释条件规则 | 节点、边、邻接矩阵及随机结构 |
| 主要计算 | 对条目选择、视觉匹配、条件属性预测 | 图传播或图结构学习 |
| 对象层级 | 原有父子关系列表，用于语义输入或逻辑规则 | 可能用作图中的边 |
| 主方法的随机语义结构 | 不使用 | 通常是方法组成部分 |
| 主张的机制 | 对象和图像决定知识的适用性 | 随机结构、拓扑或传播改善泛化 |
| 随机化实验 | 只打乱描述归属，作为独立负对照 | 随机图可能属于主模型 |
| 结果命名 | 独立 route/protocol/run ID | 独立 route/protocol/run ID |

本方案的主方法不引入随机连边、随机邻接矩阵、GCN/GAT、图消息传递或随机语义节点生成。层级关系可以是逻辑规则的输入；读取父子关系列表本身不等于使用图传播。

训练的随机初始化、minibatch 洗牌和知识负对照均不计作研究路线的随机语义结构。负对照明确标记 `control_type = text_label_shuffle`，不称为“随机语义图”，不并入主方法名称。

若后续加入任何图生成或传播机制，必须建立第三个或另一独立 route，不再作为本条件语义规则方案的补丁。两条路线在相同 backbone、split、训练预算下可以比较；不能把各自效果相加后算作同一个贡献。

## 4. 第一阶段：先实现图像参与的知识条件分支 Gv2

### 4.1 保留什么

- 保留 C 的视觉 backbone、300 维 GloVe 初始化器和已使用的 primitive 描述。
- 不启用 v1 的静态 K 校准，`lambda_static = 0`。
- 保留原 A/C/D/E 结果、配置、cache 和校验和。
- 新建实验 protocol 与目录，使用 `Gv2` 标签，不能覆盖原 G 或把新模型称为原 E。

### 4.2 知识表示需要改变什么

现在 C 将描述平均为一个类向量。Gv2 应保留：

- 类名称；
- 每条 object-extension 描述；
- 每条 attribute-extension 描述；
- object-induction 中的父子关系；
- 描述 mask、来源、复核状态。

以独立条目和关系类型编码，而不是只把同样的模板平均向量再接一个 MLP。第一版可继续使用 300 维 GloVe，对条目分别编码。对照模型必须拿到相同描述条目，以排除“新模型多看了一些知识”的解释。

实现上使用按对象/属性索引的描述表、条目 mask 与规则表，不构造邻接矩阵。object-induction 保留为已有的父子规则列表，不执行节点间消息传递。

类词表可以使用；知识构建过程不能读取 train/val/test 组合身份、测试图片或测试标签。所有对象和属性采用相同生成与缺失处理策略。复核子集在看模型输出前确定，保留复核来源；不要按是否提升指标挑知识。

### 4.3 最小可实现结构

保留 C 的联合分数，新增一个随图像变化的残差：

\[
s_{Gv2}(x,o,a)=s_C(x,o,a)+\gamma\,g(x,o,\mathcal K)\,\Delta(x,o,a,\mathcal K).
\]

其中：

- `g` 控制知识分支的使用强度；
- `Delta` 必须同时依赖图像、候选对象、候选属性及知识；
- 同一个 `(o,a)` 换图像后，知识贡献应允许变化；
- 通过知识条目选择或关系编码生成语义依据，不能只有独立于图像的 `h(e_ao_K)`。

一个用于工程验证的低秩形式是：

\[
q(x,o)=U_vv(x)\odot\sigma(U_oe_o),\qquad
\Delta(x,o,a,\mathcal K)=\langle q(x,o),r^{\mathcal K}_{o,a}\rangle.
\]

`r` 由同一组分条描述和显式关系编码得到，可按对象分块生成；图像还可以参与描述条目的选择。这里给出的是原型结构，乘法调制本身不是创新声明。必须与同知识输入的通用融合对照比较。

推荐把它具体化为下面的条目选择流程：

1. 为每个属性保留若干描述条目 `d[a, r]`，并为每个对象保留描述及父类名称。这些内容和归属固定来自知识文件。
2. 用图像特征与候选对象语义形成查询 `q(x, o)`，在属性的描述条目上计算注意力/匹配分数。
3. 设置一个贡献为零的 `null` 条目，让知识不足以解释图像时存在退出路径。`null` 权重高不自动证明模型可靠，仍需压力测试和对照。
4. 将选中的描述与图像的匹配证据转成条件属性残差，而非使用对象—属性的固定可行性惩罚。
5. 保存条目权重和分支贡献，用相同知识、不同图像检查模型是否选择了不同语义，并分析这些变化是否帮助了正确预测。

例如，同一个属性在不同对象下可能具有不同视觉含义；具体例子必须来自数据集现有词表和经检查的知识条目，不能为了支持方法再增加测试标签导向的描述。

这一路径关注显式语义依据及其对象条件适用性。通用的多描述注意力仍属于重要对照；只有新增的条件关系约束和相应证据成立，才讨论区别于已有语义变体方法的贡献。

工程要求：

- 对所有候选组合评分，不先对对象做 argmax。
- 不显式生成 `B x N x M x D`；使用低秩维度和 object chunk。
- 最后一层残差投影可零初始化，其他层正常初始化，使起始输出能复现 C，并保留有效梯度。避免将所有路径都乘以不可学习的零。
- 知识缺失时有明确 fallback；不能通过缺失 mask 暗示 seen/unseen 身份。
- 不将组合身份作为独立可训练 lookup，以免未见组合没有训练信号。

### 4.4 概率公式与实现要一致

工程试验可以先保留 legacy score 来隔离结构影响，但此时只能称为条件分数模型。

若论文要严格声称：

\[
P(a,o\mid x,\mathcal K)=P(o\mid x)P(a\mid o,x,\mathcal K),
\]

应单独实现并验证对象分布与每个对象下的属性分布归一化，训练与推理采用相同的温度及组合方式。同步建立采用相同概率头的 `C_prob_v2` 对照。先在完整词表上定义分布，再使用既定候选 mask；不能把未归一化的加法分数直接称为概率。

legacy 与 probability v2 的结果分表记录，不能把评分协议变化的收益计入知识模块。

## 5. 最小实验矩阵：先检验机制，不直接铺满 A-H

以下是新实验定义，名称不复用 v1 的 D/E：

| 实验 | 内容 | 排除的解释 |
|---|---|---|
| C-budget | C 按同等新增训练预算继续训练 | 只是多训练了几轮 |
| C-generic | 相同知识条目、近似参数量的普通融合 | 只是增加描述输入或容量 |
| C-static-v2 | 相同知识编码生成静态偏置 | 只是学会新的组合常识偏置 |
| Gv2 | 图像与候选对象参与知识条件分支 | 核心候选机制 |
| Gv2-shuffle | 从头训练，打乱知识归属，保持条目数量及长度分布 | 只是噪声或通用正则化 |
| Gv2-no-object | 保留候选标签，移除知识利用中的对象条件交互 | 对象条件交互是否必要 |

另做推理时知识打乱/遮蔽，作为敏感性诊断。不能仅凭推理时性能下降证明有效利用，因为任意训练输入遭到破坏都可能损害模型；主要证据来自重新训练的对照。

这里的 shuffle 只改变文本条目与对象/属性标签的对应，不生成图、边或随机语义向量。单独记录训练种子与描述置换种子。随机语义图若要比较，应作为另一条算法路线加入独立实验表，不代替这一负对照。

所有版本匹配知识输入、训练样本、增广、优化步数、checkpoint 选择规则和 backbone 冻结策略；记录参数量、GPU 时间、峰值显存。结构不同无法完全匹配的部分要写明。

## 6. 执行顺序与投入门槛

### 阶段 0：冻结与必要检查

1. 冻结现有 UT A/C/D/E 和 lambda selection。
2. 继续既定 MIT / C-GQA A/C 验证，判断当前文本知识的跨数据集表现；这些实验提供背景证据，不能单独证明新机制。
3. 检查知识中是否存在明显错误关系、过强典型属性、GloVe OOV 和模板重复。
4. 查看服务器上的真实 forward 和 train/eval 接口，再确定代码改动位置。当前文档没有提供已实现的服务器训练脚本。

### 阶段 1：UT 单种子的工程试验

以相同 C checkpoint 初始化各版本，并给出相同新增训练预算。第一轮可冻结 backbone，只训练相关投影和新 head；C-budget 也采用相同的冻结与更新规则。这个阶段只能判断是否值得进一步投入。

先完成 C-budget、C-generic、C-static-v2、Gv2 四项。若 Gv2 明显无收益，先检查梯度、输出退化和知识质量；在预先限制的调参预算后停止本版本。

出现可重复的改善，再运行 Gv2-shuffle 与 Gv2-no-object。主指标沿用 VAL CW AUC，CW HM、OW AUC 与 OW unseen 作为次指标/约束，规则在运行前写入 protocol。不要看到结果后更换主指标。

当前阶段建议暂沿用既有保护范围：CW HM 不下降超过 0.5 pp、OW AUC 不下降超过 0.5 pp、OW best-unseen 不下降超过 2 pp。它们是本项目的实验选择约束，不是论文录用标准。任何修改都需要另一个清楚记录的 protocol。

### 阶段 2：重复验证

固定结构和搜索范围，在 UT 与第二个数据集进行至少 3 个配对种子验证。按相同种子报告 `Gv2-C-budget`、`Gv2-C-generic`，给出每种子差值、均值和标准差。少量种子不能自动支持统计显著性声明。

继续投入需要看到：

- Gv2 相对 C-budget 和 C-generic 的改善具有重复性；
- 在第二个数据集方向基本一致，或能用预先定义的数据特征解释差异；
- 重新训练的知识打乱版本削弱收益；
- 对象条件交互的消融支持该机制；
- OW 表现没有持续性明显退化。

若只有单次 UT 的小幅正数，继续定位为探索结果，不能直接扩展成完整论文结论。

### 阶段 3：再实现条件逻辑分支 Hv2

Gv2 通过后，使用已有 LOGICZSL 三类关系构建 adapter，比较：

| 版本 | 作用 |
|---|---|
| F-external-v2 | 相同文本输入 + 外部逻辑损失 |
| Gv2 | 直接知识条件分支 |
| Gv2-external | Gv2 + 普通外部逻辑损失，作为组合对照 |
| Hv2 | Gv2 + 与条件预测节点一致的逻辑约束 |

Hv2 要说明每条规则作用于哪个预测节点，描述节点如何得到图像证据，以及属性规则如何适配对象条件。沿用原论文中关系的语义，不把典型描述随意升级成必然蕴含。

不要把联合 pair score 任意 sigmoid 后当成所有逻辑节点的可信概率。若 hierarchy node 由子节点按定义计算，再约束同一关系，检查损失是否成为恒等式；需要独立且有意义的预测节点或明确的结构约束。

只有 Hv2 的条件适配有额外证据，才能主张它优于“直接加 LOGICZSL loss”。若逻辑损失无收益，主模型可以保持 Gv2，但贡献描述也应相应缩小。

### 阶段 4：正式实验与论文判断

冻结方法与验证集选择后，完成三个数据集的完整训练、多种子、CW/OW 与消融，再按锁定规则评估 test。扩展模型失败的版本仍留在结果记录中。

仅在条件机制、噪声知识处理、跨数据集收益及与已有工作的差异都得到支持后，讨论正式论文定位。能改善性能、方法具备足够新意、达到 TPAMI 稿件要求是三个不同的判断，当前均不能保证。

## 7. 能支持与不能支持的结论

### 支持继续做的信号

- 同一组合的知识分支会随图像证据改变；这种变化可对应具体描述或关系。
- 知识在对象正确而属性错误的样本中帮助属性判断，而非仅通过对象分数变化提高指标。
- 通用融合、静态偏置和知识打乱均不能解释新增收益。
- 在知识替换/缺失的预定压力测试中，模型能合理减弱知识分支，而非固定奖励常见组合。

图像变化导致输出变化只是实现检查，不是有效性的证明。还要检查对错误与正确预测的实际作用。

### 应停止或重做本版本的信号

- 知识分支长期接近零，性能与 C-budget 一致。
- 随机打乱的知识获得同样收益，或普通同容量融合获得同样收益。
- 图像条件移除后无损，说明尚不能支持所声称的图像条件机制。
- 只有扩大搜索预算、换主指标或看 test 后挑参数才能得到正结果。
- 加入逻辑项使结果持续恶化。

门控接近零表示当前版本主动退回 C，不能写成知识机制成功。诊断一次、有限调整后仍失败，就保留负结果并修改方案。

主实验统一记录 `knowledge_representation = description_rule_table`、`uses_graph_propagation = false`。文件冻结时保存知识原文和条目顺序的 hash；若与随机语义图方案共享知识原文，分别记录各自额外处理及 hash。

## 9. 与已有工作的关系：运行前需明确的区别

本轮检索能确认以下重叠，不能据此宣称整个候选方案已经完成全面新颖性审查：

- CPF 已有文本描述和对象引导属性学习，新增模块必须给出超出这两点的机制与对照。[CPF，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Wu_A_Conditional_Probability_Framework_for_Compositional_Zero-shot_Learning_ICCV_2025_paper.html)
- LOGICZSL 已有关系知识和逻辑损失，候选贡献不能仅为将其损失接入 CPF。[LOGICZSL，CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/papers/Wu_LOGICZSL_Exploring_Logic-induced_Representation_for_Compositional_Zero-shot_Learning_CVPR_2025_paper.pdf)
- CANet 已研究图像与对象条件下的属性表征，普通条件属性 head 不是新的研究问题。[CANet，CVPR 2023](https://arxiv.org/abs/2305.17940)
- CAMS 已使用 gated cross-attention，添加 gate 本身不能作为新颖性依据。[CAMS 预印本](https://arxiv.org/abs/2511.16378)
- EVA 已研究语义变体与专家对齐，采用多描述/多专家时要明确与其差异。[EVA，ICLR 2026](https://openreview.net/pdf?id=hUtTGobe1r)

需要围绕“显式关系怎样进入条件属性预测”“知识得到什么图像证据”“何时允许退回视觉判断”建立逐项区别；若最终没有可辨别的机制差异，应修改贡献定位。
