## 5. shuffle 控制到底在对照什么

本文件中的 shuffle donor 指该类别在 C_shuffle 中借用谁的三条描述；它不是这三句原文的所属类别。原文三句始终属于标题中的目标类别。

已检查材料、对象分别构成无自配对的一一映射：16 个材料供体、12 个对象供体均无遗漏和重复。这个结构检查通过，不等于每次交换都产生充分语义破坏。

有些交换跨越很不同的鞋型/材质，有些只在邻近材料或共同结构间交换。例如 Leather←Faux.Leather、Full.grain.leather←Nubuck、Sheepskin←Wool、Slippers←Loafers 仍可能保留部分相关语义。反过来，踝靴←凉鞋、高跟鞋←高筒靴的差别较明显。以下是文本层面的判断，不是已测得的向量距离或性能影响。

## 6. 放到当前 GloVe 编码中怎样理解

已读取 [原构建器快照](<C:/Users/llenovo/Documents/ChatGPT/CZSL/tmp/ekr_source_fixture/tools/build_knowledge.py>) 的 description_tokens、make_primitive_table，以及 [transition/bank.py](<C:/Users/llenovo/Documents/ChatGPT/CZSL/ekr_cpf_transition_20261005_v1/transition/bank.py>) 的 construct。当前方案使用 GloVe 词向量均值，不是 CLIP 文本编码器，也不是能完整理解句法的上下文句子编码器。

设类别为 c，N(x)=x/max(||x||₂,ε)，h_c=N(名称词向量的均值)。第 r 句只保留 GloVe 中存在的词，得到 d_cr=N(这些词向量的均值)；无可用词向量时回退到名称向量。正常情况下：

$$p_c^{text}=N\!\left(\frac{h_c+d_{c1}+d_{c2}+d_{c3}}{4}\right).$$

C_shuffle 保留目标类别自己的名称 h_c，只将三句描述整组换成供体 π(c) 的句向量：

$$p_c^{shuffle}=N\!\left(\frac{h_c+d_{\pi(c)1}+d_{\pi(c)2}+d_{\pi(c)3}}{4}\right).$$

这意味着：

1. 泛词不是“没有作用”。cloth、surface、finish、soft、smooth 等都会进入均值；但作用可能是改变原型方向，而非加入可区分的视觉知识。
2. 三条近义句可能反复强调同一方向。是否真的导致原型聚集、残差不足或性能下降，需要向量诊断和实验，不能只凭阅读断言。
3. 否定、因果和限定关系在词平均中不能得到完整表达。增加“not necessarily narrow”并不是稳妥修复，因为 narrow 仍会进入均值；更适合直接使用正向、准确的结构词。
4. shuffle 仍有正确名称及供体中的共有词。不能把它称为“完全随机且没有类别语义”。这里也没有构建随机图，它只是描述归属对照，与 USG 随机语义图路线保持独立。
5. 名称与三句各占一个归一化向量槽位；这不等于名称必然主导结果，也不等于词数更多的句子必然权重更高。

本次没有重新扫描完整 GloVe 文件、计算各类余弦距离、重建 bank 或复跑 GPU 评估；不能据此声称已测得以上机制。

| Cotton / Wool 的组织形式 | 先依据训练图决定可写的纹理，不自动指定 woven 或 knitted | 不用未经核验的“粗织纹”“针织线圈”替换。 |
| Synthetic 的统一表面 | 暂不编造统一可见表面；保留宽类别身份并记录异质性 | 这是类别本身的限制，不能通过措辞强行制造一个专属纹理。 |

建议按以下顺序推进：

1. 保存 v1 原字典、缓存、置换、结果与本次批注；在单独目录建立 knowledge_v2_draft，先处理表中的 P1 项。
2. 从 **train split** 生成固定抽样图册：建议每类最多 20 张，使用预先固定的 seed，覆盖不同训练组合，类内不够则全取。材料类尽量跨鞋型，对象类尽量跨材料。图册记录样本路径、材料、对象和抽样规则；只用于核验描述，不用验证/测试错误挑句子。20 是人工工作量建议，不是统计验收阈值。
3. 对每句分别记录：是否符合标签含义、是否在图中可见、是否在不同训练组合中成立、是否只是共有特征。典型而非全覆盖的描述要标注覆盖范围；不可见性能移到背景说明，不能充当可见证据。
4. 对难区分材料承认边界：真皮/仿皮、尼龙/其他织物、人造材料宽类不能仅靠几个词保证视觉可分。不要为凑满三句写假的独特特征；若无法写出三句可靠候选，v2 仍保持 draft。
5. 冻结真正核验过的 v2 文本后，单独生成 v2 缓存/bank，记录来源、逐项审阅记录、hash、标签顺序、OOV/fallback 和置换。保持类别标签、GloVe、300维编码、归一化、每类句数及训练预算与对照一致；修改句数、聚合器或编码器则视为额外方法变化，需独立控制。
6. 先比较 v2 的 C_text、C_shuffle 与 A_unit；保留 v1 的结果，按相同训练 seeds 0、3351、2026 进行配对。A_unit 仅在代码、配置、预算和输入确实不变时复用。若复核多个描述置换，应预先固定并报告全部结果；三次训练 seed 不是三次描述置换。
7. 保持已声明的选择指标、guard 和研究门槛。只有重新获得合规的语义收益证据，才决定是否进入正式 EKR；v1 的负结果仍报告。

以上是操作顺序，不是现有 CLI 已经支持新知识库的保证：当前 bank.py 会校验原 C 缓存来源 hash。v2 不能直接覆盖原字典或指向旧缓存来绕过检查，应作为新的独立知识/缓存版本接入。

## 8. 对当前实验结论的影响

你前面的 UT 三 seed 结果是 C_text−A_unit 平均约 +2.432 pp，C_text−C_shuffle 平均约 −0.267 pp。CPU 产物审计全 PASS 说明记录与配置能够对上，但未做 GPU checkpoint 复放；研究门槛未通过说明尚未证明正确描述比当前置换描述更有收益。

这次查到文本质量问题，给出了可检验的修订方向；没有证明修订后一定提升，也没有证明 EKR 一定失败。不能因此把研究门槛改为通过。更准确的当前表述是：**描述扩充改变了模型原型并相对名称归一化对照带来改善，但语义归属的收益尚未得到支持；需要先修正与核验描述，再开展冻结协议下的复核。**
