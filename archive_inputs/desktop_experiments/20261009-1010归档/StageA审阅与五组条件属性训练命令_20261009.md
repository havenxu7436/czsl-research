## 2. B/F 为什么没有明显收益：这次新增了什么证据

检查真实最佳 B/F 权重，在共同的 12 张 TRAIN 图片上做 3 个 batch × 4 张的梯度诊断。范围只包括 `objc_embedder` 与 `attrc_embedder` 的映射参数，不是全网络或整轮平均。没有 optimizer step，原参数/持久 buffer 未变。

| 模型 / batch | 加权逻辑梯度范数 ÷ CPF 梯度范数（%） | 两者 joint 余弦 | AE 对 CPF 属性映射余弦 |
| --- | ---: | ---: | ---: |
| B / 0 | 0.173641 | −0.078817 | −0.525454 |
| B / 1 | 0.125785 | −0.025536 | −0.121123 |
| B / 2 | 0.186475 | +0.075767 | +0.546016 |
| F / 0 | 0.163277 | −0.135612 | −0.816586 |
| F / 1 | 0.061759 | −0.093917 | −0.316922 |
| F / 2 | 0.215217 | +0.036731 | +0.298409 |

这些 batch 上，加权逻辑梯度约为 CPF 的 0.062%–0.215%；CPF 与总损失 joint 梯度方向几乎相同。与此同时，AE 在部分 batch 上与 CPF 属性学习明显冲突。我的判断是：当前实现的逻辑项对这些映射的影响较弱，且方向并不稳定有利，因此不宜直接大幅提高 β；提高权重可能同时放大冲突。

这只是“弱且部分冲突”的诊断支持，不证明它就是 AUC 下降的唯一原因，也不能等同于 Adam 实际更新方向。只有 3 个小 batch，不能推广为所有训练阶段或所有参数的结论。OI/OE 对属性映射的零梯度符合现有路径；它们仍可通过对象侧影响其他部分，不应误报为逻辑完全断连。

下一步优先检验：把正确 OE/AE 作为图像与候选对象条件下的属性证据，是否比同结构名称、错误知识归属及普通融合更有效。不是再加一份无条件知识，也不是现在换骨干。

GT-object 仅用于监督条件属性损失与诊断；正式预测同时计算全部候选对象，不使用真实对象。新 head 用到了已有视觉特征，但没有学习更好的视觉骨干。所有组仍站在已经使用知识的 C_text 上，因此这里检验的是“新增条件知识模块的增量”，不是全部知识从无到有的效果。

## 8. 不根据结果修改的投入门槛

本次 seed 0 budget gate 沿用既定方案，同时要求：P_K−C_text 的 CW AUC ≥0.20 pp；P_K−P_name ≥0.10 pp；P_K−两种 perm 平均 ≥0.10 pp。保护项相对 C_text：CW HM ≥−0.5 pp、OW AUC ≥−0.5 pp、OW best-unseen ≥−2 pp。两种 perm 的各自差值仍完整报告，不用平均数遮盖其中一组更强。

门槛是是否值得继续投入的规则，不是统计显著性。通过才优先锁定方案做另两个 seed，并各用自己的 C_text checkpoint/特征；不能三 seed 共用 seed 0 的视觉缓存。仅名称/打乱同涨时归因于容量或适配，不归因于正确知识；只有 NLL 改善时不称识别收益；GT-object 属性改善但组合指标不改善时，检查对象边缘与候选竞争。P_generic 更强需要补它自己的匹配名称/错配控制，再谈机制。

旧静态知识 gate=false 保持原样；本步不是原 Troika+LogiCZSL 完整论文复现，也不评估新方法 TEST。不要同时开 β 搜索、换视觉骨干和改知识句子，以免无法解释这五组结果。
