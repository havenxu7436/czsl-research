# SG-EKR 下一步具体实践命令（2026-10-08）

本轮运行的是一个新的 **SG-EKR（support-gated EKR）seed-0 pilot**。它使用 TRAIN-only 的对象条件双折支持度筛选描述槽，固定 GloVe 值向量，只训练查询、键、空槽与总增益，共 28,834 个参数。三组严格配对条件为：

- `G_name`：只允许属性名称槽；
- `G_support`：名称槽加 TRAIN-only 支持度通过的描述槽；
- `G_shuffle`：使用同一支持掩码和同等容量，但把描述槽替换为冻结 shuffle 对照。

旧 name pilot gate 和 v2 alignment gate 仍然保持 `false`。本轮不是绕过旧 gate 去跑旧 Stage C，而是用独立目录检验一个新假设。旧 Stage C 不能运行；本轮自己的 integrity 检查和 decision gate 也不能忽略。

## 2. 在服务器校验并解压

登录服务器后执行：

```bash
PY=/data/xhw/miniconda3/envs/cpf/bin/python
ZIP=/tmp/sgekr_support_mask_20261008.zip
UNPACK=/tmp/sgekr_launch_20261008_v1
EXPECTED_ZIP_SHA256=17d840dc0cf2033a4b34cc09ff92b6e83d68671e218578a88a0d163a326cf23d

echo "$EXPECTED_ZIP_SHA256  $ZIP" | sha256sum -c -
"$PY" -m zipfile -t "$ZIP"
test ! -e "$UNPACK" || { echo "STOP: unpack directory already exists: $UNPACK"; exit 2; }
mkdir -p "$UNPACK"
"$PY" -m zipfile -e "$ZIP" "$UNPACK"

BUNDLE="$UNPACK/sgekr_support_mask_20261008"
"$PY" "$BUNDLE/verify_release.py"
cat "$BUNDLE/validation.json"
```

预期看到：

```text

SG-EKR RELEASE CHECKSUM PASSED 8
```

这里使用 CPF Python 的绝对路径，因此当前显示 `(base)` 或忘记 `conda activate cpf` 都不影响运行。

## 3. 用 tmux 启动

```bash
tmux new -s sgekr_ut
```

进入 tmux 后重新设置变量：

```bash
PY=/data/xhw/miniconda3/envs/cpf/bin/python
BUNDLE=/tmp/sgekr_launch_20261008_v1/sgekr_support_mask_20261008
```

默认输出目录要求至少 5 GiB 可用空间。

## 4. 先运行 prepare

```bash
bash "$BUNDLE/run.sh" prepare
```

prepare 会完成发布包校验、旧输入哈希校验、8 个 CPU 单元测试、原 name anchor 重放、TRAIN-only 支持掩码生成和三组同初始化检查。它不会训练新模型。

查看准备结果：

```bash
cat "$OUT/status.json"
cat "$OUT/prepare_checks.json" | "$PY" -m json.tool
"$PY" -c "import json; p=json.load(open('$OUT/support_mask.json')); print('selected_ae_slots=',p['selected_ae_slots'],'present_ae_slots=',p['present_ae_slots'],'threshold=',p['threshold'])"
```

必须满足：

- `status` 为 `prepared`；
- `prepare_checks.json` 中 `passed` 为 `true`；
- `selected_ae_slots` 大于 0 且小于 `present_ae_slots`。

如果 prepare 报哈希、重放、数据身份或 integrity 错误，不要绕过。保留终端输出并停止。

## 5. 训练三项 pilot

```bash
bash "$BUNDLE/run.sh" train
```

顺序是 `G_name`、`G_support`、`G_shuffle`，每项 seed 0、3 epochs。以此前四项 v2 pilot 约 75 分钟为参照，本轮三项通常约 **55–70 分钟**，另加 prepare/report 数分钟；实际时间以服务器负载为准。

按 `Ctrl+B`，松开后按 `D` 可退出 tmux。重新连接：

```bash
tmux attach -t sgekr_ut
```

## 6. 训练完成后汇总

只有看到三次 `SG-EKR RUN COMPLETE` 后才运行：

```bash
bash "$BUNDLE/run.sh" report
```

查看结果：

```bash
cat "$OUT/reports/integrity.json" | "$PY" -m json.tool
cat "$OUT/reports/decision.json" | "$PY" -m json.tool
cat "$OUT/reports/results.csv"
sha256sum "${OUT}_review.zip"
```

`integrity.json` 的 `passed` 必须为 `true`。`decision.json` 中 `proceed` 为 `true` 时，只表示允许设计一个冻结的多 seed 确认实验；仍然不要运行旧 Stage C。`proceed` 为 `false` 时，停止 SG-EKR 预算并保存全部正负结果。

## 7. 中断后的续跑命令

先回到 tmux，重新设置 `BUNDLE` 和 `OUT`，然后执行：

```bash
export SGEKR_OUT=/var/tmp/czsl_xhw_sgekr_20261008
bash "$BUNDLE/run.sh" resume
bash "$BUNDLE/run.sh" report
```

`resume` 会校验 protocol、发布包、支持掩码、冻结 anchor、已提交 checkpoint 和最佳 checkpoint；已经完成的分支会验证后跳过。不要对部分训练目录再次使用 `train`。

如果错误发生在任何 `last_epoch.pth` 建立之前，保留原目录并换新版本：

```bash
export SGEKR_OUT=/var/tmp/czsl_xhw_sgekr_20261008_v2
bash "$BUNDLE/run.sh" prepare
bash "$BUNDLE/run.sh" train
bash "$BUNDLE/run.sh" report
```

## 9. Gate 的处理原则

- 可以在新协议中记录旧 gate 为 false 并验证新假设，因为新协议不是旧 Stage C。
- 不能把旧 gate 改成 true，不能删除旧负结果，也不能使用旧 Stage C 命令。
- 不能忽略发布哈希、输入哈希、重放、配对、冻结权重、checkpoint 或 review ZIP 的 integrity 错误。
- 不能忽略本轮 gate。`G_support` 必须在 CW AUC 上分别超过 `B_name`、`G_name` 和 `G_shuffle` 至少 0.10 个百分点，同时通过 CW HM、OW AUC 和 OW unseen guards，才允许进入下一轮多 seed 确认。
