# ZSCL TPAMI 扩写实验设计指南（可执行版）

> 目标：将 LogiCZSL (CVPR 2025) 的结构化语义知识与 CPF (ICCV 2025) 的条件概率分解统一为一个 **Knowledge-Constrained Conditional Composition Framework**，用于支撑 TPAMI 投稿中的核心实验验证。  

---

## 0. 总体原则

本实验不是简单验证 “CPF + LogiCZSL loss” 是否有效，而是要验证如下核心命题：

$$
P(a,o\mid \mathbf{x},\mathcal{K})
\approx
P(o\mid \mathbf{x})P(a\mid o,\mathbf{x},\mathcal{K})
$$

其中：

- $a$：attribute；
- $o$：object；
- $\mathbf{x}$：输入图像；
- $\mathcal{K}$：来自 LogiCZSL 的结构化语义知识，包括 object-induction、object-extension、attribute-extension，以及 object-attribute compatibility prior；
- $P(a\mid o,\mathbf{x},\mathcal{K})$：TPAMI 版本需要重点证明的 knowledge-conditioned conditional attribute prediction。

核心实验目标：

1. 验证结构化知识 $\mathcal{K}$ 是否能提升 CPF；
2. 验证 $\mathcal{K}$ 直接进入条件概率建模是否优于仅作为 external logic loss；
3. 验证 Full Model 是否优于 naive combination；
4. 验证收益来源不是 prompt length、随机 prior 或数据泄露。

---

## 1. 实验主线

### 1.1 原始 CPF

CPF 将 CZSL 建模为：

$$
P(a,o\mid \mathbf{x}) = P(o\mid \mathbf{x})P(a\mid o,\mathbf{x})
$$

组合预测：

$$
\hat{c}=\arg\max_{(a,o)} P(o\mid \mathbf{x})P(a\mid o,\mathbf{x})
$$

### 1.2 TPAMI 版本目标

引入结构化知识 $\mathcal{K}$：

$$
P(a,o\mid \mathbf{x},\mathcal{K})
\approx
P(o\mid \mathbf{x})P(a\mid o,\mathbf{x},\mathcal{K})
$$

最终 pair-wise logit 推荐写为：

$$
s(a,o\mid \mathbf{x},\mathcal{K})
=
z_o
+
z_{a\mid o}^{\mathcal{K}}
+
\lambda_k \cdot \mathrm{Prior}(K_{oa}[o,a])
$$

其中：

- $z_o$：object logit；
- $z_{a\mid o}^{\mathcal{K}}$：knowledge-conditioned attribute-under-object logit；
- $K_{oa}\in\mathbb{R}^{|\mathcal{O}|\times|\mathcal{A}|}$：object-attribute compatibility prior；
- $\mathrm{Prior}(\cdot)$：对 $K_{oa}$ 的稳定化变换；
- $\lambda_k$：compatibility calibration 权重。

## 3. 三条知识注入路径

### 3.1 路径 1：输入端 richer text features

目标：用 LLM 生成的对象/属性描述增强 CPF 的文本嵌入。

构建：

$$
W_o^{\mathcal{K}},\quad W_a^{\mathcal{K}},\quad W_{a\mid o}^{\mathcal{K}}
$$

| 嵌入 | 维度 | 内容 | 用途 |
|---|---:|---|---|
| $W_o^{\mathcal{K}}$ | $N\times d$ | object name + object-extension descriptions | 替换 CPF 原始 $W_o$ |
| $W_a^{\mathcal{K}}$ | $M\times d$ | attribute name + attribute-extension descriptions | 替换/增强 attribute classifier |
| $W_{a\mid o}^{\mathcal{K}}$ | $N\times M\times d$ 或稀疏字典 | object-conditioned attribute text | 路径 3 feature-level module |

推荐聚合方式：

```python
def encode_text_set(texts, text_encoder, mode="mean"):
    """
    texts: list[str], e.g., ["dog", "tail-wagging", "floppy-eared"]
    return: 1 x d normalized embedding
    """
    emb = text_encoder(texts)  # L x d
    emb = F.normalize(emb, dim=-1)

    if mode == "mean":
        out = emb.mean(dim=0)
    elif mode == "attention":
        query = emb[0:1]  # class name as query
        weights = torch.softmax(query @ emb.T / math.sqrt(emb.size(-1)), dim=-1)
        out = (weights @ emb).squeeze(0)
    else:
        raise ValueError(mode)

    return F.normalize(out, dim=-1)
```

### 3.2 路径 2：输出端 object-attribute compatibility calibration

目标：在 pair-wise score 上加入 $K_{oa}$ 语义兼容性先验。

不要使用：

```python
o_detected = p_o.argmax()
p_a = p_a * K_oa[o_detected]
```

正确做法是对所有 candidate pairs 同时 joint scoring：

$$
s_{a,o}
=
z_o
+
z_{a\mid o}^{\mathcal{K}}
+
\lambda_k \cdot \mathrm{Prior}(K_{oa}[o,a])
$$

推荐先实现两种 prior 形式：

**方案 A：centered prior**

$$
\mathrm{Prior}(K_{oa}) = \frac{K_{oa}-\mu(K_{oa})}{\sigma(K_{oa})+\epsilon}
$$

**方案 B：clamped log prior**

$$
\mathrm{Prior}(K_{oa}) = \log(\mathrm{clip}(K_{oa}, \tau, 1.0))
$$

推荐初始选择方案 A，数值更稳定。

```python
def normalize_K_oa(K_oa, mode="centered", tau=0.05, eps=1e-8):
    """
    K_oa: N x M, values in [0, 1] or raw compatibility scores.
    return: N x M prior logits.
    """
    if mode == "centered":
        return (K_oa - K_oa.mean()) / (K_oa.std() + eps)
    elif mode == "clamped_log":
        return torch.log(torch.clamp(K_oa, min=tau, max=1.0))
    else:
        raise ValueError(mode)
```

### 3.3 路径 3：特征端 knowledge-conditioned module

目标：让知识通过可微模块直接参与 $z_{a\mid o}^{\mathcal{K}}$ 的估计，而不是只做 prompt enhancement 或 post-hoc calibration。

#### 重要工程约束

不要直接 materialize 超大张量：

$$
B\times N\times M\times D
$$

尤其是 C-GQA 中 $N\approx 674, M\approx 413$，直接 pair-wise expansion 会造成显存爆炸。

优先采用 **factorized scoring** 或 **chunk-wise pair scoring**。

```python
W_o_K = []
for obj in objects:
    texts = [obj] + object_extension_descriptions.get(obj, [])
    W_o_K.append(encode_text_set(texts, text_encoder, mode="mean"))
W_o_K = torch.stack(W_o_K, dim=0)  # N x d
torch.save(W_o_K, "W_o_K.pt")
```

### 4.3 构建 $W_a^{\mathcal K}$

```python
W_a_K = []
for attr in attributes:
    texts = [attr] + attribute_extension_descriptions.get(attr, [])
    W_a_K.append(encode_text_set(texts, text_encoder, mode="mean"))
W_a_K = torch.stack(W_a_K, dim=0)  # M x d
torch.save(W_a_K, "W_a_K.pt")
```

### 4.4 构建 $W_{a\mid o}^{\mathcal K}$：必须避免 seen/unseen coverage bias

不能只给 seen pairs 构建高质量描述，而给 unseen pairs 置零。否则模型可能把“是否有显式 pair knowledge”当作 seen/unseen 信号。

推荐统一策略：

1. 所有 candidate pairs 都使用 template fallback：

$$
e_{a\mid o}^{\mathrm{template}}
=
\mathrm{TextEncoder}(\text{``a } o \text{ that is } a\text{''})
$$

2. 对少量或全部 pairs 可以额外使用 LLM-enhanced description；
3. 若只对 seen pairs 有 LLM description，必须做消融并报告 coverage bias 风险。

推荐实现：

```python
def build_pair_text(obj, attr):
    return [
        f"a {obj} that is {attr}",
        f"the {attr} {obj}",
        f"{attr} appearance of {obj}",
    ]

W_ao_K = torch.empty(N, M, d)
for i, obj in enumerate(objects):
    for j, attr in enumerate(attributes):
        texts = build_pair_text(obj, attr)
        # Optional: append LLM-conditioned description if available.
        if (obj, attr) in pair_llm_descriptions:
            texts += pair_llm_descriptions[(obj, attr)]
        W_ao_K[i, j] = encode_text_set(texts, text_encoder, mode="mean")

torch.save(W_ao_K, "W_ao_K_template_or_llm.pt")
```

如 $N\times M\times d$ 太大，可按 object 保存：

```text
W_ao_K/
├── obj_000.pt  # M x d
├── obj_001.pt
└── ...
```

### 4.5 构建 $K_{oa}$

推荐三种版本都保存，便于消融：

| 版本 | 说明 |
|---|---|
| `K_oa_text.pt` | 仅由 CLIP/text similarity 得到 |
| `K_oa_llm.pt` | 仅由 LLM feasibility 得到 |
| `K_oa_mix.pt` | text + LLM 混合 |

若暂时没有 LLM feasibility，不要把 `K_llm` 设为全零后再混合。应使用：

$$
K_{oa}=K_{\text{text}}
$$

或把未查询的 LLM feasibility 设为中性值 0.5。

```python
def build_K_oa_text(objects, attributes, W_o_K, W_a_K, W_ao_K):
    """
    W_o_K:  N x d
    W_a_K:  M x d
    W_ao_K: N x M x d
    """
    K = torch.zeros(len(objects), len(attributes))
    for i in range(len(objects)):
        for j in range(len(attributes)):
            pair_emb = W_ao_K[i, j]
            proto = F.normalize((W_o_K[i] + W_a_K[j]) / 2, dim=-1)
            K[i, j] = F.cosine_similarity(pair_emb[None], proto[None]).item()

    # Normalize to [0, 1]
    K = (K - K.min()) / (K.max() - K.min() + 1e-8)
    return K
```

### 4.6 数据泄露检查

必须确认：

- $K_{oa}$ 不使用 test composition 的 existence annotation；
- prompt 中不包含 train/test split 信息；
- open-world 下不使用 evaluation candidate set 的存在性作为先验；
- 使用 soft calibration，不使用 hard 0/1 filtering；
- 所有 LLM outputs 和清洗规则可追溯。

## 5. Phase 2：MVP 实现

MVP 包括路径 1 + 路径 2 + optional external logic loss。

### 5.1 替换 CPF 文本输入

```python
# Original
q_t = softmax(f_v2t(v_h_c) @ W_o.T / sqrt(d)) @ W_o

# MVP
q_t = softmax(f_v2t(v_h_c) @ W_o_K.T / sqrt(d)) @ W_o_K
```

attribute classifier 中类似替换 $W_a\rightarrow W_a^{\mathcal K}$。

### 5.2 加入 $K_{oa}$ calibration

```python
# z_obj:       B x N
# z_attr_obj:  B x N x M
# K_prior:     N x M

score_ao = (
    z_obj[:, :, None]
    + z_attr_obj
    + lambda_k * K_prior[None, :, :]
)

score_ao = apply_candidate_mask(score_ao, setting)
```

`lambda_k` 推荐：

- 初始设为 0.05 或 0.1；
- 可设为 learnable scalar，但需要 clamp 到合理范围，例如 $[0,1]$；
- 优先在 UT-Zappos 上调参。

### 5.3 MVP 变体

单数据集单 seed 先跑以下 6 个变体：

| 变体 | Text K | $K_{oa}$ calibration | Logic loss | 目的 |
|---|:---:|:---:|:---:|---|
| A | — | — | — | CPF baseline |
| B | — | — | ✅ | external logic loss |
| C | ✅ | — | — | richer text only |
| D | — | ✅ | — | calibration only |
| E | ✅ | ✅ | — | path 1+2 |
| F | ✅ | ✅ | ✅ | MVP full |

### 5.4 Gate 1：MVP 是否通过

MVP 继续扩展的最低条件：

- A–F 都能正常训练和评估；
- E 或 F 相对 A 在 AUC/HM 上有正收益；
- 若 F 明显低于 E，需要降低 `beta` 或暂时不加 logic loss；
- 训练曲线无明显震荡或 NaN；
- $K_{oa}$ prior 不导致 open-world unseen performance 大幅下降。

## 6. Phase 3：Full Model 的 feature-level knowledge-conditioned module

### 6.1 推荐实现：factorized logit head

避免 $B\times N\times M\times D$ 大张量。

推荐把 pair score 分解为三部分：

$$
z_{a,o}^{\mathcal K}
=
z_{a}^{\mathrm{vis-txt}}
+
z_{o}^{\mathrm{vis-txt}}
+
z_{a,o}^{\mathrm{pairK}}
$$

其中：

$$
z_a^{\mathrm{vis-txt}} = \langle \phi_a(v_a), \psi_a(e_a^\mathcal K)\rangle
$$

$$
z_o^{\mathrm{vis-txt}} = \langle \phi_o(v_o), \psi_o(e_o^\mathcal K)\rangle
$$

$$
z_{a,o}^{\mathrm{pairK}} = h(e_{a\mid o}^{\mathcal K})
$$

示例代码：

```python
class FactorizedKnowledgeConditionedHead(nn.Module):
    def __init__(self, d_vis, d_txt, hidden_dim=512):
        super().__init__()
        self.attr_vis_proj = nn.Linear(d_vis, hidden_dim)
        self.attr_txt_proj = nn.Linear(d_txt, hidden_dim)
        self.obj_vis_proj = nn.Linear(d_vis, hidden_dim)
        self.obj_txt_proj = nn.Linear(d_txt, hidden_dim)

        self.pair_bias = nn.Sequential(
            nn.Linear(d_txt, hidden_dim),
            nn.GELU(),
            nn.Linear(hidden_dim, 1),
        )

    def forward(self, v_attr, v_obj, e_attr_K, e_obj_K, e_ao_K=None):
        """
        v_attr:   B x M x Dv
        v_obj:    B x N x Dv
        e_attr_K: M x Dt
        e_obj_K:  N x Dt
        e_ao_K:   N x M x Dt, optional
        return:   B x N x M
        """
        q_a = F.normalize(self.attr_vis_proj(v_attr), dim=-1)
        k_a = F.normalize(self.attr_txt_proj(e_attr_K), dim=-1)
        z_a = torch.einsum("bmd,md->bm", q_a, k_a)  # B x M

        q_o = F.normalize(self.obj_vis_proj(v_obj), dim=-1)
        k_o = F.normalize(self.obj_txt_proj(e_obj_K), dim=-1)
        z_o_aux = torch.einsum("bnd,nd->bn", q_o, k_o)  # B x N

        z = z_o_aux[:, :, None] + z_a[:, None, :]  # B x N x M

        if e_ao_K is not None:
            pair_bias = self.pair_bias(e_ao_K).squeeze(-1)  # N x M
            z = z + pair_bias[None, :, :]

        return z
```

说明：

- 这个版本只 materialize $B\times N\times M$ score，不 materialize $B\times N\times M\times D$ feature；
- 参数少，显存可控；
- 若 $N\times M$ score 仍太大，使用 object chunk。

### 6.2 Chunk-wise scoring 备选实现

```python
def chunked_pair_scoring(z_obj, z_attr_obj_fn, K_prior, lambda_k, chunk_size=64):
    """
    z_obj: B x N
    z_attr_obj_fn: function that returns B x chunk_N x M for object chunk
    K_prior: N x M
    """
    B, N = z_obj.shape
    scores = []
    for start in range(0, N, chunk_size):
        end = min(start + chunk_size, N)
        z_attr_chunk = z_attr_obj_fn(start, end)
        score_chunk = (
            z_obj[:, start:end, None]
            + z_attr_chunk
            + lambda_k * K_prior[None, start:end, :]
        )
        scores.append(score_chunk)
    return torch.cat(scores, dim=1)
```

## 7. Logic loss adapter

### 7.1 为什么需要 adapter

LogiCZSL 的 logic loss 原本作用于概念节点分数：

$$
s_k[v]\in[0,1]
$$

其中 $v$ 可以是 object、attribute、description 或 hierarchy node。CPF 的输出包括：

- object logits $z_o$：$B\times N$；
- pair scores $s_{a,o}$：$B\times N\times M$；
- attribute-under-object logits $z_{a\mid o}$：$B\times N\times M$。

不能直接把 $B\times N\times M$ pair scores 输入原始 logic loss。

### 7.2 推荐 adapter

构建概念节点分数：

```python
class LogicScoreAdapter(nn.Module):
    def __init__(self, desc_embeddings=None):
        super().__init__()
        self.desc_embeddings = desc_embeddings  # optional, frozen

    def forward(self, z_obj, score_ao, image_feat=None):
        """
        z_obj:    B x N
        score_ao: B x N x M
        image_feat: B x D, optional for description-node scores
        """
        out = {}

        # Object score: B x N
        out["object"] = torch.softmax(z_obj, dim=-1)

        # Attribute score: B x M, marginalize over objects
        out["attribute"] = torch.softmax(torch.logsumexp(score_ao, dim=1), dim=-1)

        # Pair score: B x N x M
        out["pair"] = torch.sigmoid(score_ao)

        # Description-node scores, if needed
        if image_feat is not None and self.desc_embeddings is not None:
            desc_logits = image_feat @ self.desc_embeddings.T
            out["description"] = torch.sigmoid(desc_logits)

        return out
```

### 7.3 对三类 logic loss 的输入建议

| Logic loss | 需要的 score | 推荐来源 |
|---|---|---|
| $\mathcal{L}_{oi}$ object-induction | object/hierarchy node score | `softmax(z_obj)` + hierarchy node text similarity |
| $\mathcal{L}_{oe}$ object-extension | object + object description score | object score + image-description CLIP similarity |
| $\mathcal{L}_{ae}$ attribute-extension | attribute + attribute description score | logsumexp over object dimension + image-description CLIP similarity |

若 description node score 暂时难以实现，Phase 2 可以先只接入 $\mathcal{L}_{oi}$，确认稳定后再接入 $\mathcal{L}_{oe}, \mathcal{L}_{ae}$。

### 7.4 Delayed logic loss schedule

如果加入 logic loss 后训练不稳定，采用：

$$
\beta(t)=
\begin{cases}
0, & t < T_{\mathrm{warmup}}\\
\beta_{\max}\cdot \frac{t-T_{\mathrm{warmup}}}{T_{\mathrm{ramp}}}, & T_{\mathrm{warmup}}\le t<T_{\mathrm{warmup}}+T_{\mathrm{ramp}}\\
\beta_{\max}, & \text{otherwise}
\end{cases}
$$

## 8. Attribute loss 的定义

### 8.1 问题

如果 $z_{a\mid o}^{\mathcal K}$ 或 `score_ao` 是 $B\times N\times M$，而 attribute label 是 $B$，不能直接：

```python
loss_att = CE(score_ao, labels.attr)
```

需要先得到 $B\times M$ 的 attribute logits。

### 8.2 推荐实现 1：GT-object conditioned attribute loss

训练时使用 ground-truth object：

```python
def attribute_loss_gt_object(z_attr_obj, attr_labels, obj_labels):
    """
    z_attr_obj: B x N x M
    attr_labels: B
    obj_labels: B
    """
    B = z_attr_obj.size(0)
    z_attr = z_attr_obj[torch.arange(B), obj_labels, :]  # B x M
    return F.cross_entropy(z_attr, attr_labels)
```

优点：稳定，语义明确。  
缺点：训练时使用 GT object，推理时不用；需在论文中说明这是辅助 loss。

### 8.3 推荐实现 2：object-marginalized attribute loss

```python
def attribute_loss_marginalized(z_attr_obj, attr_labels):
    """
    z_attr_obj: B x N x M
    """
    z_attr = torch.logsumexp(z_attr_obj, dim=1)  # B x M
    return F.cross_entropy(z_attr, attr_labels)
```

建议：

- Phase 2/3 首选 GT-object conditioned；
- supplementary 中可对比 marginalized 版本。

## 9. 训练与推理框架

### 9.1 训练伪代码

```python
for batch in dataloader:
    images, pair_labels, attr_labels, obj_labels = batch

    visual_feats = visual_encoder(images)

    # Path 1: text-enhanced object learning with W_o_K
    v_obj = text_enhanced_object_learning(visual_feats, W_o_K)  # B x N x D

    # CPF object-guided attribute learning
    v_attr = object_guided_attribute_learning(visual_feats, v_obj)  # B x M x D or compatible

    # Path 3: feature-level K module
    z_attr_obj_K = knowledge_head(
        v_attr=v_attr,
        v_obj=v_obj,
        e_attr_K=W_a_K,
        e_obj_K=W_o_K,
        e_ao_K=W_ao_K,
    )  # B x N x M

    z_obj = object_classifier(v_obj)  # B x N

    # Path 2: compatibility calibration
    score_ao = (
        z_obj[:, :, None]
        + z_attr_obj_K
        + lambda_k * K_prior[None, :, :]
    )  # B x N x M

    score_ao = apply_train_candidate_mask(score_ao, setting)

    # Losses
    loss_com = composition_loss(score_ao, pair_labels)
    loss_obj = F.cross_entropy(z_obj, obj_labels)
    loss_att = attribute_loss_gt_object(z_attr_obj_K, attr_labels, obj_labels)

    if use_logic_loss:
        concept_scores = logic_adapter(z_obj, score_ao, image_feat=visual_feats.global_feat)
        loss_logic = logic_loss(concept_scores)
    else:
        loss_logic = 0.0

    loss = loss_com + alpha1 * loss_att + alpha2 * loss_obj + beta * loss_logic

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

## 10. 消融实验设计

### 10.1 核心消融表

最终主表至少包括以下 8 个变体：

| 变体 | Text K | $K_{oa}$ calib | Feature K module | Logic loss | 目的 |
|---|:---:|:---:|:---:|:---:|---|
| A. CPF-only | — | — | — | — | 原始 baseline |
| B. CPF + external K | — | — | — | ✅ | LogiCZSL-style external loss |
| C. CPF + richer text | ✅ | — | — | — | 测试 text knowledge |
| D. CPF + calibration | — | ✅ | — | — | 测试 $K_{oa}$ |
| E. CPF + text + calib | ✅ | ✅ | — | — | MVP 路径 1+2 |
| F. CPF + naive full K | ✅ | ✅ | — | ✅ | MVP + external logic |
| G. CPF + feature K | ✅ | ✅ | ✅ | — | feature-level K |
| H. Full Model | ✅ | ✅ | ✅ | ✅ | 最终方法 |

### 10.2 关键判断

| 命题 | 必要对比 |
|---|---|
| Full Model 优于 CPF | H > A |
| Full Model 优于 external loss | H > B |
| Full Model 优于 naive combination | H > F |
| Feature K module 有贡献 | G > E |
| Logic loss 在 feature K 上仍有增益 | H > G |
| 路径 1+2 有 MVP 价值 | E > A 或 F > A |

不强求 C > B 或 D > B。关键是 H 是否稳定优于 A/B/F/G。

### 10.3 Sanity checks

必须至少完成：

| 实验 | 目的 |
|---|---|
| Shuffled descriptions | 打乱 object/attribute descriptions，排除 prompt length effect |
| Random $K_{oa}$ | 用随机矩阵替代真实 prior，排除随机 bias |
| Uniform $K_{oa}$ | 全 1 或常数矩阵，确认 calibration 不是常数偏移 |
| Template-only $W_{a\mid o}$ | 不使用 pair-level LLM，检查 template fallback 效果 |
| No-pair-knowledge | 去掉 $W_{a\mid o}$，只保留 $W_o^K,W_a^K$ |

## 12. 备注

本实验的关键不是让所有组件堆叠后取得最高数值，而是形成一条清晰证据链：

$$
\text{CPF}
\rightarrow
\text{CPF + external K}
\rightarrow
\text{CPF + embedded/conditioned K}
\rightarrow
\text{Full Knowledge-Constrained Conditional Composition}
$$

最终 TPAMI 论文需要证明：结构化知识不仅是外部正则项，而是能够作为条件变量参与 $P(a\mid o,\mathbf{x},\mathcal K)$ 的估计，并在 unseen compositional generalization 中带来可解释、可复现、非平凡的增益。
